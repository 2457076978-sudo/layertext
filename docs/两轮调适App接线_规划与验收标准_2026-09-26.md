## 二、设计定案

1. **复用回炉模式架构**（09-18「AI 简化本章」先例）：R2 编排抽进 core 纯函数，App 只做调用与进度呈现；**不在 App 里 spawn CLI 脚本**（node PATH 地雷刚在 A3 治过，不新增 spawn 依赖）。
2. **core 化**：从两轮调适.mjs 抽 `planRound2(progress, feedbackText, reportReds, tier)` → `{ segs, dims, promptParts, gate }`——问题段∪反馈维度段的选定、幅度档位折算（复用 `adaptcheck.parseTeacherFeedback`）、**两轮闸门判定一并进 core**，CLI 与 App 同一实现。
3. **App 执行器**：复用 App AI 会话机制逐段请求（prevTail 衔接、[P##] 补回、单段一次不重试=CLI 同纪律）；进度 JSON 与 CLI 同形状（中断恢复两端兼容）；执行完写终稿+调适报告（复用 CLI 的报告生成函数，必要时同样 core 化）。
4. **按钮语义**：任务单 `confirmed && 反馈文件存在 && gate.ok` → 「▶ 开始第二轮修订」可点；否则禁用，title 写明缺什么（三件套纪律）。执行中进度行显示 `N/M 段`；完成后 toast+状态行引导去检视图看调适状态块。
5. **AI 配置**：用 App 自己的 AI 设置（教师看得到用的是哪家）；验收用 mock AI（mockIPC 分块协议配方），保证 byte-equal 测试不花钱不碰网。

## 三、验收标准（机器可查）

| # | 标准 | 怎么验 |
|---|---|---|
| A | `planRound2` 与 CLI 旧路径同输入同输出 | 抽取时 CLI 侧等价测试：合成夹具（反馈+进度+红项）两边输出 deep-equal |
| B | 两轮闸门进 core：`round:2` 进度 → `gate.ok=false` 含人话理由 | 单测锁 |
| C | 按钮状态机：confirmed/反馈/gate 三条件 | DOM 测试（_dom_env 配方）：缺任一条件禁用且 title 含原因 |
| D | 端到端同形：App 路径 R2 产物 == CLI 路径产物 | 合成书 mock AI 下终稿+调适报告 byte-equal |
| E | 第三轮拒绝：R2 完成后再点按钮 → 拒绝提示不执行 | DOM 测试 |
| F | 回放兼容：进度 JSON 新旧形状互读 | 回放夹具跑一遍 |

## 四、明说不做（本项边界）

- **R1 初稿生成不进 App**：批量管线属 CLI 战线（整章多段长时间运行），App 只接"教师反馈后的第二轮"——教师主路径闭环的最短缺口。
- 不做学生端任何东西；不改两轮调适制的三维目标矩阵与阈值（尺子不动）。
- 不引入新的 AI 供应商配置面（就用 App 现有 AI 设置）。
