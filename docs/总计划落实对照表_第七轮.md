# 《LayerText 工程优化总计划》落实对照表（第七轮）

> 第五轮：阶段 3 两条验收 + 回放覆盖全书 + App 层 catch 审计 · 第六轮：学生版发布 + 教师稳定身份 + 任务实验
> 本轮判定口径不变：**有实现 + 有自动化断言 + 验收证据**，三者齐才写 ✅。
>
> 起点 `HEAD = b9a1252`（第五十二批之后）。

本轮的输入是《LayerText 第七轮质检报告》（`05-网站与AI工作区/LayerText第七轮质检报告.md`）。
报告给了 3 项 P0、3 项 P1 与一组 P2 工程流程项；调查阶段又核实出**三个报告没写到的事实**，
全部随批次落地：

1. 未提交的工作树改动是一个**完整功能**（教师稳定 ID + 教师任务实验），`readRunIdentity`
   的归一化大改就在其中——P0-② 的任何修复都会动同一区域，必须先收口（→ 批次 0）；
2. P1-⑤ 比报告写的更重：发布包不只"只读第一层"，还把裸层键 `'A'` 直接当日志文件名，
   而实际文件按标签命名（`决定/A层85.jsonl`）——**`decisionCount` 实际恒为 0**；
3. `会话改写.mjs` 的 `LEXICON_VERSION` 是第二个绕过身份直读全局指针的同病点。

## 一、P0：本轮必须先收口

### 1.1 工作树收口（P0-①）✅

`git status --short` 显示 7 个修改文件 + 6 个未跟踪文件 + 3 个 dist 目录。它们不是垃圾：
是一个完整功能（`TeacherRegistry` 稳定 ID、教师任务实验、App 面板接入、学生版入清单扫描）。
处理：

- 先跑全量 verify——**基线并不绿**：lint 挡着 1 error + 1 warning，`studentversion.test.ts`
  的端到端用例还有两处自身缺陷（清单路径少了 `.json` 后缀；断言按 run 布局找包、
  fixture 却是 legacy 布局）。逐一修复后基线 831 项全绿（含子代理新增的 65 项）。
- 分五个逻辑提交收口（`7bad913`…`3d64c81`），`.gitignore` 收编 `dist-*/`
  （多人并行测试各自的 tsc 输出）。
- **验收**：`git status --short` 为空；干净 checkout（`git worktree add`，HEAD=`aa04a98`，
  只软链 node_modules）上 `npm run verify` 全绿 841 项。

### 1.2 清单指针：全局"最新"不再是发布事实源（P0-②）✅

`发布包.mjs` 的 `loadManifest` 原来无条件优先读全局 `清单_最新.json`——与
`readRunIdentity` 已解析出的身份**完全脱钩**。并发时会把 A 老师的清单打进 B 老师的发布包，
且导出照常 exit 0。重写为：

- 身份来源「显式指定 / 按教师分片」→ 按 `RUN.runId` 点名读 `清单_<runId>.json`；
- 身份来源「最近一次」→ 仅当该教师名下**恰有一份**运行分片指针时放行（`teacherRunShards`），
  多份即歧义，exit 2 提示 `--run`；
- 身份 legacy（含并发串线退回）→ exit 2，提示 `--run`；
- 读到清单后校验 `runId` 与教师归一化 ID **双一致**，不符 exit 2；
- 全局 `清单_最新.json` 在发布路径上一份都不读。

同病点一并修：`会话改写.mjs` 的 `LEXICON_VERSION` 从"直读全局指针"改为
`readManifest(P, RUN.runId)` + runId 校验——别人的词库版本就是假答案。

- **验收**（`tests/bundle_cli.test.ts` 双教师并发用例）：wayne/ada 各建运行后，
  被串线的一方不带 `--run` 必须 exit≠0 且提示 `--run`；带 `--run` 各自导出，
  包内 `runId`/`teacher` 与本人一致、ada 的包含她自己的产物。

### 1.3 缺件即拒：部分包一个文件都不许出现（P0-③）✅

`collectFiles` 把缺件放进 `skipped` 后照常 `buildBundle`、建目录、写描述——
产生"结构完整但缺件"的部分包，而收件人只会核对包描述里**有的**那些件，
缺件在他那边根本不出现，于是"缺件"看起来就像"完整"。现在 `skipped.length > 0`
即打印全部缺件（**产物身份 + 路径**，不只路径）并 exit 1，不创建任何目录。

- **验收**：删掉正文后导出 → exit 1、输出含 `art-…` 身份、目标目录零新文件。

## 二、P1：产品可信度

### 2.1 原子替换导出（P1-④）✅

旧实现覆盖同名目录只 `console.warn`"旧的多余文件不会被删"——重复导出后，
上一次的残留文件混在包里，`--check` 会把它报成"夹带"，收件人分不清是旧文件还是真夹带。
现在：staging 目录写入 → `verifyBundle` 自检（刚写的每一件读回核对）→ rm 旧目录 →
`renameSync` 原子替换；任何一步失败清理 staging，最终目录一个字不动。

- **验收**：导出后塞一个"上轮残留"文件再导出 → 残留消失、`--check` 通过。

### 2.2 决定日志全层统计 + 层级口径唯一（P1-⑤）✅

两层问题：`doExport` 只读 `m.tiers[0]` 一层；且层键/标签错位（`'A'` vs `'A层85'`），
实际 `decisionCount` 恒为 0（报告只发现了前者，调查核出了后者）。修法按"唯一口径"原则：

- `resolvePath` **入口**归一层级（`tierTagOf` 落在请求上，而不是某个局部变量——
  `logTail` 与各路径分支必须吃同一个值）。写侧一直传标签、读侧传裸层键从此解析到同一文件。
- `doExport`/`doWhere` 遍历 `m.tiers` 全部层合并决定事件。

- **验收**：三层各一条决定 → 包描述 `decisionCount === 3`（报告验收原标准）；
  单测钉死"传 `'A'` 与 `'A层85'` 对五种产物类型解析同一路径"。

### 2.3 学生版 derivedFrom（P1-⑥）✅

学生版是从教师工作稿减出来的派生物，但登记里没有任何指向源稿的字段——
另一个团队只能知道"谁生成"，不知道"从哪一件减、按哪版规则减"。现在
`RunArtifact.derivedFrom`（登记事实，不是身份成分；旧清单不迁移，读取时按同规则算得出）：

| 字段 | 值 |
|---|---|
| `sourceId` | 同章正文的产物身份（`artifactIdOf`，与正文那条登记同值） |
| `sourcePath` | 源稿相对产物目录的路径 |
| `transformer` | `LayerText_AF学生版@<项目版本>` |
| `ruleVersion` | 引擎 `STUDENT_VERSION_SCHEMA_VERSION`（=1） |
| `dropSections` | 引擎 `DEFAULT_DROP_SECTIONS`（`['词句卡']`） |

落点在**登记侧**（`清单.mjs` scanArtifacts 学生版分支——登记是唯一事实源），
引擎常量直接 import 不抄写；发布包把 `derivedFrom` 原样带进包描述 entries。

- **验收**：端到端断言登记字段逐一正确；单测断言 `buildBundle` 传递且 `verifyBundle` 不受影响。

## 三、P2：口径与门禁

### 3.1 partial 章显式声明三件套 ✅

第十章只有 3 段（`3/223` 的全书权重）——第五轮对照表已定性："要不要排除在全书口径外
是**口径决定**，不是技术决定"。第七轮拍板：**显式声明**（脚本不猜），
partial 章**仍登记、仍回放**（半成品也要有人守），但不进全书分母，发布默认拒绝。

- 清单：`RunManifest.partialChapters` + `--partial-chapter 10`（整组替换，可清空，摘要显示）；
- 冻结回放：`--partial 10` 冻进 cfg（冻结与 `--check` 同口径）；每章质检带
  `completeness: 'complete' | 'partial'`；全书定位的排除章**点名列出**；
- 发布：partial 章的学生版默认 exit 2；`--allow-partial` 放行且 `run.partialChapters`
  写进包描述——收件人必须看得见"这份包里有还没写完的章"。

- **验收**：重冻带 `--partial 10` 的样本逐项断言（completeness/全书 9 章/排除章点名/覆盖不退场/
  声明入 cfg）；CLI 拒发（exit 2、零新文件）与放行（包描述声明）用例；包描述单测。
  真实 AF 项目的第十章要生效，需在真实清单上跑一次 `--partial-chapter 10`（见交接提醒）。

### 3.2 TDZ 冒烟门禁 ✅

TDZ 已四次发生（第二/三/五轮对照表、CHANGELOG），它是**运行期**缺陷——`tsc` 与
`node --check` 都不报。新增 `tests/pipeline_smoke.test.ts`：对 `tools/af_pipeline/` 全部 20 个
.mjs 做**零成本冒烟**（坏项目指针让脚本在加载阶段失败，约 30ms/个、全套约 1 秒），
模块顶层先于业务分支执行——顶层 TDZ 当场炸。退出码不设预期（找不到项目是正确的失败），
只守"不许以 TDZ / ReferenceError 的方式死"。

- **验收**：**反证通过**——放入真 TDZ 脚本（`console.log(THING); const THING=1;`）时
  门禁当场红并点名脚本与错误行，删除后恢复绿。
- 发布脚本"空输入 / 缺件 / 重复运行 / 并发运行"四格矩阵即批次 1 的 bundle_cli 测试本身，
  不另起炉灶。

### 3.3 教师名录边界（声明，不写代码）✅

`src/core/teachers.ts:61-66` 的边界注释继续有效并在此重申：
**名录只归一化身份（谁是谁），不是权限系统**——它不回答"谁能改哪一层哪本书"、
不授权发布、不读他人班级数据。发布授权、多租户隔离属**商业化前置工作**，
在本地优先架构（对象目录 + SQLite 索引）跑通多书多教师之后另行设计，
本轮不引入任何授权代码（引入半套权限比没有权限更危险）。

## 四、本轮明确不做（边界）

| 项 | 不做的理由 |
|---|---|
| 四格实验 | 阶段 4 的**必要证据**（会话上下文 × 词表注入 × 人工成本的因果），工程测试全绿不能替代它；另行安排 |
| 多租户 / 同步服务 | 报告长程项；本地优先存储先跑通再谈 |
| 教师工作台实测 | 需要 ≥3 位真人教师（首次点击、撤销、疲劳），不是代码能替代的验收 |
| 发布包加密/签名 | 报告未要求；当前核对机制（哈希 + 身份自洽 + 排除声明）够用 |
