## 一、本轮主体：阶段 3「最关键的迁移」——路径解析收口

计划原话：

> **最关键的迁移是把路径解析集中到一个 `Resolver`，禁止业务代码拼目录**；
> 把词表和词典读取结果冻结为带哈希的 `LexiconSnapshot`，传入所有阶段。
> 旧 CSV/JSON 只做一次导入，不再作为新的事实源。

第一轮的审查结论是：引擎层（`manifest` / `LexiconSnapshot` / `Resolver` / `decisiondb` / `withLock`）是真的且有用例，
但**接线层只做了一半**——17 个管线脚本里只有 4 个接了 `Resolver`。本轮把这个收口做完。

### 1.1 结果

| | 改造前 | 改造后 |
|---|---|---|
| 接了 `Resolver` 的脚本 | 4 / 17 | **15 / 17** |
| 仍在手拼**产物**路径的脚本 | 11 | **0** |
| 手拼的产物路径表达式 | 24 处 | **0 处** |

剩下 2 个（`重制_生成.mjs`、`重制_预处理与规则.mjs`）**刻意不改**，理由写在代码里：
它们读写的是**原文目录**（源树），而 `Resolver` 建模的是**产物目录**。
硬塞进去只会给源树编一套并不存在的 `ArtifactKind`。诊断这段在 `LayerText_AF重制_生成.mjs` 的文件头。

### 1.2 引擎侧新增的两个 `ArtifactPathKind`

原来有几类产物**根本无法用"层+章+日期"描述**（汇总报告跨层跨章，它只有一个名字），
于是脚本只能手拼。新增：

| kind | 用途 | legacy 落点 | run 落点 |
|---|---|---|---|
| `汇总报告` | 人读的汇总（三档汇总 / 台账总览 / 四格实验报告 / 风险队列报告） | `<产物>/<名字>_<日期>.md` | `<产物>/_运行/<runId>/<名字>_<日期>.md` |
| `运行中间产物` | `_运行/` 下的机器读产物（四格实验原始数据、入库提议） | `<产物>/_运行/<名字>[.ext]` | `<产物>/_运行/<runId>/<名字>[.ext]` |

`PathRequest` 相应加了 `name?: string`（产物名）。

**「迁移不许改动落点」是用断言钉住的**：18 条 legacy 路径逐字符比对通过（`/tmp` 自检脚本，
比对项含正文/台账/复核报告/风险队列/会话日志/决定日志/版本日志/两种新 kind）。
换句话说，这次改动在 legacy 下**对教师是完全不可见的**——这正是"不破坏教师已有工作流"的硬约束。

### 1.3 过程中抓到的三个真实缺陷

| # | 缺陷 | 为什么危险 |
|---|---|---|
| 1 | **`清单.mjs --stamp` 的布局取自命令行，而不是取自它刚读的那份清单** | 建清单时用了 `--layout run`、刷状态时忘了再写一遍 → 扫描按 legacy 去找产物 → **一件都扫不到、清单记 0 件，而输出照旧写「清单已更新」**。实测复现并已修（布局以清单为准，命令行与清单打架时**说出来**） |
| 2 | `汇总报告` 的 run 分支漏了日期 | 同一种产物在两种布局下**名字不同**，于是下游"按名字找文件"只对其中一种成立。已改为与 legacy 同名、只换目录 |
| 3 | 若干脚本的 `R` / `RR` 定义落在使用之后、或引用了尚未定义的层级常量（TDZ） | 会直接崩，但只在运行到那一句时才崩。已用**自带的 `argRun`** 取代各脚本自己的参数助手（它们的定义位置各不相同，有的还是 `args.includes` 风格） |

### 1.4 逐个脚本的端到端证据

`tests/pipeline_gate.test.ts` 里新增 6 条，每条都**断言文件落在哪**——
只断言"跑通了"没有意义：写在错地方照样退出 0。

- 对照台账：`run` 布局下台账与总览落进运行私有目录，且**产物根目录不再出现它们**
- 三档复核：报告落进运行私有目录，且**报告里确实读到了产物**（断言不出现"读不到/缺产物"——
  只看文件存在是不够的，"读不到 → 记 0 → 照样写报告"也会通过）
- 风险队列：人读的 Markdown 报告与机器读的 JSON **都在运行私有目录**（两者本来就在不同目录）
- 清单：台账按解析器登记，相对路径带运行私有前缀
- **布局以清单为准**：`--stamp` 不带 `--layout` 也要扫得到 run 布局的产物（缺陷 #1 的回归）
- **两种布局各跑一次**：同一份输入，`legacy` 落产物根、`run` 落运行私有目录

## 二、阶段 3 的另一半：发布包与溯源（原来完全缺失）

第一轮的如实记录里，阶段 3 的「导入导出通过 manifest」「学生数据默认不出包」
「任意发布文件可查询出处」三条都标着 ❌。本轮补齐。

### 2.1 新建 `src/core/bundle.ts`

| 计划要求 | 实现 | 证据 |
|---|---|---|
| 「导入导出通过 manifest」 | `buildBundle` / `verifyBundle` / `PublishBundle` —— 包描述回答"这份包该有哪些文件、每个文件的哈希是多少"，收件人逐件核对，而不是只能相信文件名 | `tests/bundle.test.ts`（18 条） |
| 「**打包默认不含画像、成绩和个人信息**」 | **白名单 + 黑名单 + 显式排除清单**三件事一起做 | 见下 |
| 「任意发布文件可查询『由哪次运行、哪个模型、哪版词库生成，谁在何时做了哪条决定』」 | `provenanceOf` + `decisionRow` + `renderProvenance` | `tests/bundle.test.ts` 第 10–15 条 |

**为什么是白名单而不是黑名单**：黑名单的前提是"我知道所有不该出包的东西长什么样"，
而学生数据的形式会变（今天叫 `分层_九3九4.json`，明天可能叫别的）。
白名单的前提弱得多、也更站得住：**没被明确允许的，都不出去**。
黑名单仍然保留，它挡的是"白名单种类里混进了学生数据"这种更隐蔽的情形。

要拦的是它**作为数据文件**的样子（`分层.json` / `分层_九3九4.json` / 分层正本），
而不是这个词本身——`分层阅读说明.md` 是正经文档，不该误伤。这条差异有专门用例锁住。

**排除项必须被列出来**：`excluded` 数组哪怕为空也要在。
静默丢弃让人**以为包是完整的**，静默收录才是数据事故——两者一样危险，都要有据可查。

### 2.2 新建 `tools/af_pipeline/LayerText_AF发布包.mjs`

三个动作，真跑子进程验证（`tests/bundle_cli.test.ts`，6 条）：

```
--export（默认）   按清单把该出包的产物收成一个目录 + 一份 发布包_<runId>.json
--check <包目录>   逐件核对（缺件 / 哈希不符 / 夹带学生数据），有问题以非 0 退出
--where <相对路径> 查一份发布文件的出处与它之后的决定
```

实跑输出（自检项目）：

```
════ AF 发布包 ════
 运行：T-v1-A-wayne-74132a15fc44cbf0
 书：T v1｜层：A｜章：1
 模型：deepseek-chat（提示词 session-v3-20260911）｜词库：840503268b331b21
 教师：wayne｜决定记录 0 条（**只记条数，内容不随包出去**）
 入包 2 件：正文｜…、台账｜…
 排除 0 件（本次产物里没有学生数据迹象）
```

```
════ 溯源 ════
_运行/<runId>/正文/第一章/原文_A层85_2026-01-01.md｜由运行 <runId> 生成｜模型 deepseek-chat
（提示词 session-v3-20260911）｜词库 840503268b331b21｜教师 wayne｜…｜内容与清单一致｜之后没有任何决定
```

三处刻意的诚实：

- **没有清单就不发包**（`--export` 直接以非 0 退出并说明"没有清单答不了『哪次运行』"）。
  没有清单的包只是一个压缩文件，不是可追溯的发布物。
- **查不到就如实说查不到**，并把"不编一个出处"写进那行文字里（用例断言这一句）。
- **拿不到当前内容时说"未核对哈希"，不说"对得上"**——后者是编的。
- `rejected`（系统没做成）在报告里标 `⚠`：**它不是教师的判断**，混在一起看会误读教师的行为。

**决定日志与版本日志只记条数、不进包内容**：它们含教师 ID 与逐条操作，属审计材料，
不是给学生的读物。这条取舍写在类型注释里。

## 三、还没做的（如实列）

| 计划里的要求 | 状态 | 实话 |
|---|---|---|
| 阶段 3「**锁和原子提交**覆盖并发生成、并发审校和断点续跑」 | ⚠ **部分** | 词典有锁（`withLock`，2 处调用）；账本追加已用 `O_APPEND`（第一轮）。但**正文本身的并发写仍无锁**——乐观并发（`baseVersion`）会让**后者被拒**、不会写坏，可教师会看到"稿件已经改过，请重新出队"而不知道为什么。另外 `withLock` 本身是"读-判-写"，存在竞态窗 |
| 阶段 3「默认用 `run` 布局」 | ❌ **仍未改** | 不是漏做，是**不打算单方面改**：它会让教师已有工作流换目录。正确做法是加一次显式迁移（先校验没有并发身份冲突），而不是把默认值翻过来 |
| 阶段 3「旧 CSV/JSON 只做一次导入，不再作为新的事实源」 | ❌ **没做** | 词库/词典/专名表仍被各脚本现读。`LexiconSnapshot` 已能算出哈希版本、也进了清单，但**没有"导入一次然后只读快照"的那一步** |
| 阶段 3「Run/Artifact/Teacher 三类实体有稳定 ID」 | ⚠ **部分** | Run 有（`runId`）；Decision 有（`eventId`，第一轮加）；**Artifact 仍以路径为主键**，Teacher 只是字符串 |
| 阶段 4「跑四格实验」 | ❌ **没跑** | 要花 API 额度，用户先前明确选择自己挑时机 |
| 阶段 2「今日任务」「变更历史」「暂停并恢复」 | 🔄 **本轮进行中** | 由并行子代理落地，另见该部分的记录 |
| 阶段 1「首次点击到可采纳结果的 P95 < 10 秒」 | ⚠ **有度量无数字** | `productmetrics.ts` 能算，缺真人操作数据 |
