# W2 交付报告 · 数据闭环：采纳率分析

**日期**：2026-09-06 · **状态**：✅ 完成 · **验收**：通过

## 做了什么

### 1. AI 建议台账（数据源）

新增《AI建议台账.csv》：应用内每次 AI 建议被**采纳 / 拒绝 / 直改**时自动追加一行，
与变更日志同目录（书稿文件夹；示例模式在报告目录）。变更日志仍是审计留痕（教师视角），
台账是分析数据源（机器视角），职责分开，互不干扰。

16 列：时间/书/章/层级/场景（行内·批量·自动直改·标记即改写·助手直改）/标记类型/规则号/结果/
引擎复核（⚠/通过）/供应商/模型/提示词版本（W3 起填真实版本号，现记"内置v1"）/原句/建议句/依据/拒绝原因。

**所有落盘路径都接上了**：行内 ✓、批量应用、全局直改、标记即改写、助手 apply_edit 直改、行内 ✗ 拒绝。

刻意决定：拒绝时不弹窗追问原因（新手友好红线"点 ✗ 就完事"），拒绝原因默认"未填"——
不可靠性判断改由"引擎复核 × 结果"交叉承担（见判读逻辑）。

### 2. 聚合逻辑（src/core/adoption.ts，纯逻辑无 DOM）

按 标记类型 / 规则号 / 供应商+模型 / 提示词版本 / 日期 聚合：建议数、采纳、拒绝、直改、
**明确采纳率**（采纳/(采纳+拒绝)，教师过目部分——直改不计入分母）、总接受率（含直改）、复核⚠比。
另出：最常被拒 Top5、"引擎复核 × 结果"交叉表、一句话判读 `diagnose()`：
- 复核⚠被拒率显著高于复核通过 → **该改提示词（加强规则表述）或换模型**；
- 复核通过仍高被拒 → 问题在教学偏好 → **写进「长期审校约定」**；
- 多提示词版本/多供应商自动出对比与回滚建议。

### 3. 两个消费端

- **CLI**：`node dist/tools/adoption.js <台账.csv|目录>... [--out 报告.md]`——目录递归一层聚合全部台账，
  打印 Markdown 报告可另存（跨书复盘用）。
- **应用内「复盘」页**：第 5 个视图标签 + 菜单「显示 → 复盘」。汇总卡片（累计建议/明确采纳率/总接受率/
  复核⚠被拒率）+ 按标记类型表 + 最常被拒 Top5 + 日期趋势 + 自动判读。数据来自本书台账，一键刷新。

## 验收结果（喂真实格式台账回答两个问题）

用 12 条模拟真实使用的台账（`tests/fixtures/AI建议台账_样例.csv`，含引号/逗号转义）：

- ✅ **哪类建议最不可靠**：「词汇简化」明确采纳率 20%（1/5），复核⚠比 67%——CLI 与复盘页都能直接读出；
- ✅ **该改提示词还是改规则**：复核⚠被拒率 75% vs 复核通过 25% → 判读输出"优先改提示词或换更稳的模型"；
- ✅ 49/49 测试全绿（新增 6 项：CSV 解析往返、采纳率口径、两种判读分支、版本对比、端到端样例）；
  `npm run eval` 不低于基线；app 前端 tsc + vite build 通过。

## 遗留
