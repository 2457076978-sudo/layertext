# W3 交付报告 · 提示词与供应商治理

**日期**：2026-09-06 · **状态**：✅ 完成 · **验收**：通过

## 做了什么

### 1. 提示词外置与版本化（prompts/，改提示词不改代码）

- 四份提示词迁入 `prompts/`：`system_simplify`（修订候选规则）/ `system_draft`（分层初稿任务）/
  `system_assistant`（助手身份与工具协议）/ `rewrite_sentence`（逐句改写 user 模板）。
  **v1.0 与原内置文本逐字一致，零行为变化**（动态注入部分：教师约定/书级规则仍由代码追加）。
- `prompts/manifest.json`：每份提示词独立版本号 + 整套 `setVersion` + 变更记录；`prompts/README.md`
  写明修改流程（改文件 → bump manifest changelog → 测试与 eval 全绿 → 台账自动记录新版本）。
- 加载顺序（app/src/ai.ts `loadPrompt`）：**教师自定义** `~/Documents/LayerText配置/prompts/<名>.md` 优先
  （版本记 `v1.0*`，改提示词无需重新打包应用）→ 内置（随应用分发，Vite `?raw` 打包）。
- CLI 评测（src/eval.ts）改为从 `prompts/` 读**同一份提示词**做 AI 初稿评测——评测与生产同源，
  提示词改动会直接反映在 eval 的 key 模式结果里。

### 2. 供应商 failover

- 配置：AI 设置新增「备用供应商」列表（名称/地址/模型/Key），Key 留空复用主 Key（适合同服务商多模型）；
  备用 Key 存钥匙串独立条目（`layertext.apikey.fb0/1/…`，Rust `save/load_api_key` 增加 account 参数，
  向后兼容旧调用）。
- 调用（app/src/ai.ts `callWithFailover`）：主供应商失败（网络/超时/限流/5xx/4xx，经既有自动重试仍失败）
  → 按配置顺序逐个降级；每次实际用了哪家写入成本台账（`failover=是`），切换时状态栏提示教师。
- 非流式（callChat：审核建议/逐句改写/分层初稿）与流式（chatStream：AI 助手）都走同一序列。

### 3. 成本台账

- 每次 AI 调用一行，落 `~/Documents/LayerText质检报告/AI成本台账.csv`（全局）：
  时间/场景/书/章节/供应商/模型/提示词版本/入出 tokens/耗时ms/是否 failover/结果。
- 写入点在 `callWithFailover` 内部（成功与失败都记），业务层零改动即全覆盖。
- 复盘页新增「本书 AI 成本」卡片（调用数、tokens、备用切换次数、失败次数，按书名过滤）。

### 4. 台账版本联动

W2 的《AI建议台账》提示词版本列从硬编码"内置v1"改为实际整套版本（自定义覆盖时带 `*`）——
复盘页与 CLI 分析自此可按提示词版本对比采纳率。

## 验收结果

- ✅ **新增或更换一个 OpenAI 兼容服务商只改配置**：主服务商在 AI 设置改地址/模型/Key；备用在
  「备用供应商」加一行即可，无任何代码改动；提示词修改只动 `prompts/` 或教师自定义目录。
- ✅ 纯逻辑测试 49→56 项全绿（manifest 契约、模板填充、failover 目标序列、降级判据、成本汇总往返）；
  `npm run eval` 不低于基线；app tsc + vite build + cargo check 通过。
- ✅ 台账三件套（建议台账/成本台账/变更日志）列齐备，版本号与供应商全程留痕。

## 遗留

- 备用 Key 按行序存钥匙串（fb0/fb1…），调整行顺序需重填 Key——个人使用场景可接受，记录在案；
- failover 不区分错误类型（401 也降级）——故意的：主 Key 失效时备用有独立 Key 仍可救场。
