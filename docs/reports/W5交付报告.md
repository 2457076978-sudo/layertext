## 做了什么

全部在零遥测红线内做"本地监控"——只写本机文件，导出由用户自愿。

### 1. 本地错误日志（轮转）

- 前端：`window.error` / `unhandledrejection` 全捕获 → `append_log` 命令落
  `~/Documents/LayerText质检报告/错误日志.log`（带时间戳与堆栈）。
- Rust：`std::panic::set_hook` 把未捕获 panic 也写同一日志；
  单文件超 512KB 自动轮转（`错误日志.log → .1.log → … → .5.log`，最老删除）。

### 2. 应用内「导出诊断包」

- 菜单 帮助 → **导出诊断包…**：打一个 zip（用户选择保存位置），内含：
  - `诊断信息.json`：应用版本 + 系统信息 + 配置摘要——**只含域名/模型名/开关/数量**，
    约定内容只记字数，绝不含 Key、书稿、学生文本（新增 `buildDiagSummary` 纯函数 + 隐私口径测试）；
  - `错误日志.log`（最近 128KB）；
  - `AI成本台账.csv`（最近 64KB，无文本内容）。
- 菜单 帮助 → **模拟一次错误（自检）**：一键写入一条测试错误并提示如何验证诊断包含它——
  这既是 W5 验收工具，也是日后远程支持的话术（"点这两个菜单，把 zip 发我"）。

### 3. 复盘模板（docs/复盘模板.md）

每次真实教学使用后一页纸：任务与耗时 / 卡点（新手视角）/ AI 建议质量（对照复盘页数字，
被拒典型一条 + 结构化拒绝原因勾选）/ 指标落地感 / 下一步三条。
结论反哺路径写明：改提示词（prompts/）→ 改分层方案 → 记需求。
