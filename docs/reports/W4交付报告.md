# W4 交付报告 · 发布工程

**日期**：2026-09-06 · **状态**：✅ 完成 · **验收**：通过（工作流语法与本地门禁验证；远程流水线待仓库推送后首次实跑）

## 做了什么

### 1. GitHub Actions CI（.github/workflows/ci.yml）

每次 push / PR 自动跑四道关：根目录**类型检查+全量测试**（npm test 含 tsc 构建）→
**金标准评测**（npm run eval，低于质量基线即失败——这是 W1 门禁的落地）→
**双引擎对照**（TS vs Python 参照版）→ **桌面应用 tsc 类型检查**。
不过绿不允许合并。

### 2. Release 工作流（.github/workflows/release.yml）

推 `v*` tag 触发，macOS runner：先跑与 CI 同款测试+eval 门禁（不过绿不构建）→
`tauri build --target universal-apple-darwin` 出 dmg → `tools/extract_changelog.mjs`
提取 CHANGELOG 对应版本段落作为 Release 正文（**缺段落直接失败**，防止忘写说明就发版）→
自动创建 Release 挂 dmg。

### 3. 版本与发布文档

- `docs/发布流程.md`：semver 口径、版本号出现的三处一致要求、发版五步命令、
  **"不做签名公证"的决定与理由**（个人开源项目成本考量；保留 README 右键→打开说明；
  记录了将来若需签名的改动面）、无 remote 现状的首次推送指引。
- `docs/release-checklist.md`：发布前 5 组逐项清单（质量门禁/版本与文档/产物验证/
  **新手首开路径换位 walkthrough**/发布后复盘）。
