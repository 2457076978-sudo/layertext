# LayerText 分层读 · PRD（一页）

> 产品需求文档。回答四个问题：给谁用、解决什么问题、怎么用（七步工作流）、明确不做什么。

## 1. 用户

**唯一目标用户**：把英文原著 / 分级文本改编成多个难度层、给自己学生读的英语教师（中国初中场景为主）。

- 不写代码、不熟悉 AI 配置；验收标准是**第一次打开的英语教师不看文档能走通**。
- 个人电脑单机使用；对"数据上传"高度敏感（学生相关材料绝不能出本机）。

## 2. 问题

手工把一本书简化给学生读：凭感觉控制词汇和句法难度、没有客观质检、修改不留痕、AI 改了不敢用（怕改错事实、怕越改越简单丢情节）。**LayerText 把这件事从手艺活变成有质检、有人机分工、全程可审计的流程。**

**难度观（2026-09-06 起）**：不预设 B/M/A 难度层。难度由教师词库锚定（学生学过什么词，就简化到词库内）；唯一硬标准是句长上限（默认 16 词，可调）。需要更简的版本：把简化结果再导入、再简化一遍（迭代深化，天然形成版本链）。

## 3. 七步工作流（核心场景）

| 步骤 | 动作 | 机器 / 人 |
|---|---|---|
| ① 导入 | 打开 .md/.txt/.docx，自动拆章节，**打开即自动体检** | 机器 |
| ② 配词库 | 内置课标 2022 三级 1600 词 ∪ 教材已学词 CSV ∪ 术语表 ∪ 专名表；随书稿文件夹保存 | 人配置一次，机器带全书 |
| ③ 初步诊断 | 生词/句法风险逐条勾选处理（要简化→标记清单 / 已学过→入词库）；AI 摘情节要点→教师勾选→预填要点配额 | 机器出条目，**人勾选** |
| ④ AI 简化本章 | 按词库边界+句长上限+方向指令整章逐段改写（AI），完成后自动体检；要更简=再导入再简化 | 机器出稿 |
| ⑤ 审校 | 三态高亮正文，点词/划句标记（7 词类 + 8 句类），要点配额打勾，终审四门禁 | **人握定稿权** |
| ⑥ AI 修订 | 标记 → 建议（对话/批量/逐句）→ 行内对照 → 采纳或拒绝；可选直改模式（仍留痕、原稿可还原） | 机器出候选，人拍板 |
| ⑦ 导出 | Word（含章末词句卡）/ 朗读音频 / 标记 JSON / 变更日志 CSV | 人一键 |

全程留痕：每处修改记录轮次/位置/改前/改后/规则号/依据，落盘 CSV/JSON。

## 4. 明确边界（不做什么）

- ❌ 多用户、云同步、账号体系——永远本地单机。
- ❌ 任何形式的遥测 / 自动崩溃上报 / 埋点。唯一网络请求：用户自行配置的 AI 服务商 API。
- ❌ 学生真实数据入库：示例文本全部自写 CC0；仓库/日志/文档不出现真实学生与学校文本。
- ❌ 不重写 QC 引擎骨架（有 M1 双引擎对照测试背书，只加规则）。
- ❌ 不做与"新手走通流程"无关的 UI 美化、不引入重型框架。

## 5. 成功指标

- 新手教师 ≤5 分钟从打开应用到看到第一份质检报告（首启动向导 + 四步导览保障）。
- 任何 AI 改动可追溯、可还原（变更日志 + 原始备份）。
- 引擎质量：回归测试全绿 + `npm run eval` 指标不低于 [质量基线](质量基线.md)。
