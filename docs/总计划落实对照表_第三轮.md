## 一、本轮主体一：阶段 3「原子提交」在单个文件上的落点

计划验收：「**锁和原子提交**覆盖并发生成、并发审校和断点续跑」。
第二轮修掉了锁（`O_EXCL`），但**正文本身的写入仍不是原子的**——这一半本轮补上。

`std::fs::write` / `writeFileSync` 的语义是「打开 → 截断 → 写」，
中途任何一刻失败（进程被杀、磁盘满、断电）都会留下**半份文件**。
对教师唯一的一份稿，半份比没有更糟：没有文件你知道丢了，半份文件看起来像改坏了，
而它其实已经被毁掉了。

改法：先写**同目录**临时文件 → `sync_all` → `rename` 覆盖。

- Rust 侧 `write_text_file`（App 的所有写入都经它）
- 引擎侧新增 `src/core/files.ts` 的 `atomicWriteFileSync`（管线脚本用它）
- 临时文件必须与目标同目录：跨文件系统的 `rename` 会退化成 `copy+unlink`，就不原子了
- 失败路径清掉半成品，但**清理失败不盖住真正的错误**
- 临时文件名带 pid + 随机串，两个进程写同一目标时不会互相踩

### 对照实测（子进程持续读，主进程 1 秒内连续覆盖 300KB 正文）

| | 读次数 | 看到的中间态 |
|---|---|---|
| 直接 `writeFileSync` | 7670 | **`PARTIAL:0` / `PARTIAL:8192` / `PARTIAL:24576` / `PARTIAL:40960`** |
| 原子写 `rename` | 8078 | **0 次** |

也就是"撞上半份文件"不是理论风险，而是**每秒几千次里必然发生**的事。
新增 `tests/atomicwrite.test.ts`（8 条），其中一条就是这个真并发读的观察。

一条刻意的诚实：`以 root 跑测试时权限位不起作用`，那条"写失败时旧内容一个字节都没动"
的用例会 **skip 而不是假装通过**。

## 二、本轮主体二：纪律第 2 条原来是**不成立**的

计划原话：

> 2. 任何门禁字段只能由 `gateSegment` 生成；**报告、风险队列和 App 不得重新计算同一指标**。

「哪些超纲词算『该注』」这条规则散在**四处**，而且两两不同：

| 位置 | 口径 |
|---|---|
| `qc.ts` 的 `annotable` | `w.length > 2` |
| 管线（`会话改写.mjs`） | `w.length > 2` |
| 风险队列（`风险队列.mjs`） | `w.length > 2` |
| **App 单句改写（`rewrite.ts`）** | **`t.length > 1`** ← 这一处不一样 |

后果：同一个 2 字母超纲词（`ox`、`so` 这类）在 App 里会被拦下要求加注，
在管线与风险队列里却根本不进分母——**同一个指标两个答案**。

改法两半：

1. **口径只有一处**：`ANNOTATABLE_MIN_LEN = 3` + `annotatableOf()`，定义在 `segmentgate.ts`（门禁自己那里）；
2. **门禁自己收口**：`gateSegment` 对 `input.oov` 再过一遍这条规则，**不再信任调用方传的是什么**。
   这一条才是纪律的实际落点——只要门禁自己不收口，四五个调用方里迟早会有一个传得不一样。

**为什么是潜在缺陷**：真项目实测（Animal Farm A/M 层第一章）恰好没有 2 字母超纲词，
所以这个分歧一直没露头；换一本书、换一份词库它就会浮出来，而那时没人会想到去比对两条路径的分母。
所以用例刻意用**构造出来的**输入把它逼出来。

**反证实测**（把编译产物的两条规则改回改造前，再跑同样的断言）：

```
✗ 门禁分母不受调用方影响（annotatable === 1）
✗ 2 字母词不让候选被拦（status !== blocked）
```

两条都不成立——分歧是真的，不是推测。新增 `tests/annotrule.test.ts`（9 条）。

## 三、本轮主体三：纪律第 4 条

> 4. 所有 AI 响应保存 prompt 版本、policy snapshot、模型和 traceId；
>    **没有这些字段的产物不可发布**。

后半句是**强制**的，不是"建议补上"。两半都补：

**① 补齐记录**（`会话改写.mjs`）。每条 `done` / `review` 记录原来带
`inputHash` + `promptVersion` + `model`，缺 **traceId** 与**词库版本**。
现在每段算一个 `traceId`（与 App 侧 `RewriteRequest.traceId` **同一套算法**，
于是"发布段可由 `sourceVersion + traceId` 重放"这条在两条路径上都成立），
并带上本次运行的词库快照版本。

没有清单时，词库版本如实记为「**未锁定**」——**不编一个版本号**：
编了会让"这条产物是对着哪版词库做的"变成一个假答案，而假答案比没有答案更坏。

**② 把关**（`bundle.ts` 的 `publishReadiness` + `buildBundle` 抛错）。
清单缺 `runId` / `teacher` / 模型名 / 提示词版本 / 词库版本 / 快照路径 /
输入哈希 / 产物清单中的任何一样，就**不发**，并逐条列出缺什么、为什么重要。

「抛」而不是"打个标记继续"：纪律说的是"不可发布"，不是"可以发布但标注"。
发布包 CLI 先单独报一次拒绝理由，好让人看到的是"缺字段"而不是一句从 `buildBundle` 里甩出来的长话。

**顺带被照出来的东西**：第二轮写的测试夹具其实是一份**现实中不存在的清单**
（没有输入哈希、没有产物）。这一关上马之后它立刻挂了——夹具已改成真实清单的形状。
这件事本身说明"把关"比"文档里写一句"更管用。

## 四、阶段 4「四格实验」：实验台此前**根本跑不起来**（并行落地）

计划验收：「四格实验有**可重复的输入快照和原始事件**；任一质量结论都能追溯到运行 ID」
「A/M 两条轴分别报告…**禁止综合分数替代**」。

### 4.1 先说一个必须先说的发现

`LayerText_AF四格实验.mjs` 在 HEAD 里**跑不起来**：`{ teacher: TEACHER, tier: TAG }`
用了两行之后才声明的 `const TAG`，进程在输出三行之后
`ReferenceError: Cannot access 'TAG' before initialization` 退出。

也就是说「四格实验仍未真跑」除了"要花额度"，还有一层：**实验台本身处于不可运行状态**——
而它在文档里一直写着"命令在 `docs/换书与续跑说明.md`"。
同一类 TDZ 缺陷本轮在**三个**不同脚本上出现过（另一个是第四十批那次），
说明"新加的代码块引用了什么"必须逐条核对**定义顺序**，这不是一次性的疏忽。

### 4.2 落地的东西（`src/core/experimentrun.ts` + `四格实验.mjs`）

| 验收标准 | 状态 | 证据 |
|---|---|---|
| 「有**可重复的输入快照**」 | ✅ | 快照冻住六项输入（原文逐段哈希、词表快照版本+各来源哈希、模型/温度/maxTokens、提示词版本、代码版本+**与实验有关的源码指纹**、四格定义）；`snapshotDrift` **逐项点名**"哪一项变了、从什么变成什么"，**原文漂移定位到段号**，有漂移即 `blocksConclusion=true` |
| 「有**原始事件**」且五个指标**可派生** | ✅ | `makeRawEvent` → `cellRecords` → `measureCell`，**五个指标只有这一条派生路径**（报告与 JSON 同源） |
| 「任一质量结论**可追溯到运行 ID**」 | ✅ | `traceConclusion({metric, cell}, events)`；**追不到就明说追不到**（未知指标名 / 这一格没跑过 / 截断事实不可得），**不给空数组充数** |
| 「A/M 两条轴…**禁止综合分数替代**」 | ✅ | `assertNoComposite` 递归抓 `综合\|得分\|总分\|score\|composite…`；轴的定义**复用 `positioning.ts`**，本模块不重算 |
| 「截断率」 | ✅ | 见 4.3 |

**诚实降级**做得比要求更细：`experimentStatus` 有 `未跑 / 有缺口 / 可出结论` 三态，
**未跑时 `metrics === null`**（不是 `[]`、更不是四个 0）；截断事实是
`yes / no / unknown` **三态**（没记 `finish_reason` 就是 `unknown`，**绝不是 `no`**）；
"疑似截断"（响应末尾无句终标点）作为**代理指标单独一列**，绝不冒充截断率。

### 4.3 那个 PARTIAL 由本轮补上

子代理报回来的唯一缺口落在**它不许改的文件**里：`会话改写.mjs` 的 `callChat`
只取 `content` 与 `usage`，**没记 `finish_reason`**，于是截断率只能报"算不出来"。

补的时候发现缺口其实是**三处**，而不是一处：

1. `callChat` 没返回 `finish_reason`；
2. 段级汇总时没有把每次调用的 `finishReason` 收起来、也没写进 `done` / `review` 记录；
3. **四格实验没有把 `done` 里的 `finishReason` 转发进原始事件**——
   从"日志里没有"到"事件里没有"之间隔了一次转发，很容易被误当成"上游没记"。

端到端（离线自检，`--fake exact`）：

```
报告里的截断率： 「算不出来：4 段都没记 finish_reason」  →  **截断率 0.0%**
```

0% 在这里是**真的算出来的**，不再是"没有事实支撑的假数"。
这正是子代理把截断事实做成三态的意义所在：`unknown` 与 `no` 必须长得不一样。

### 4.4 要真正产出数字，人只需要跑三条命令

```bash
npm run build
export LAYERTEXT_PROJECT="…/调适项目_AnimalFarm.json"
node tools/af_pipeline/LayerText_AF四格实验.mjs --tier A --chapters 1 --dry   # 看计划 + 快照指纹，不花钱
node tools/af_pipeline/LayerText_AF四格实验.mjs --tier A --chapters 1         # 真跑（消耗 API 额度）
```

想先免费验证实验台本身，加 `--fake exact` 即可（走同一条判定与落盘路径，不调 API）。

## 五、阶段 3 的最后一块：旧 CSV 只做一次导入（并行落地）

计划原文：「旧 CSV/JSON **只做一次导入，不再作为新的事实源**。」
在此之前，`LexiconSnapshot` 只冻**指纹**（路径/哈希/计数/抽样），数据本身没人冻——
于是多天运行里有人改了 `词库.csv`，**没有任何东西会说**。

新增 `src/core/lexiconstore.ts`（纯逻辑，不引 fs）：正本装的是**真的数据**
（已知词/待定词/专名/各来源词表/词典/知识库），版本 = 数据的内容哈希。

### 5.1 两个版本号，服务两件事

| | 是什么 | 谁在用 |
|---|---|---|
| `version` | **数据本身**的内容哈希 | 正本存档、漂移比对 |
| `snapshotVersion` | 与 `LexiconSnapshot` **同算法同输入** | **清单里记的仍是它** |

第二条是关键的取舍：如果清单改记 `version`，既有运行的 `--verify` 会凭空报一次
"词表已变"——而**假警报比没有警报更坏**（它会训练人忽略警报）。

### 5.2 漂移为什么选「拒绝」

四种可能：自动重导入（否）、警告后读旧正本（否）、警告后读 CSV（否）、**拒绝**（是）。

- 自动重导入：会在**没人看着的时候**换掉判定口径；
- 警告后读旧正本：警告会淹没在几百行里，后果是静默的；
- 警告后读 CSV：那就是改造前的行为，等于什么都没做；
- 拒绝：代价是"得跑一条命令"，收益是**永远不会有两套口径混进同一本书**。

拒绝信息里必须给修法与代价，否则只是挡路。实测原文（我在真项目副本上自己跑的）：

```
词表正本与现场对不上（…/LexiconData.json）——**不采用**。
既不用旧正本（那是拿旧口径跑新词表），也不会改读 CSV（那正是改造前的老毛病：改词表没人知道）。
· 来源「词库」内容变了（25688ce8… → 2546363d…）：…/已知词汇库_v0.7.csv
后果很具体：同一次多天运行里，前后产物的 OOV 判定会来自两份不同的词表，而两边都报告成功。
修：重新导入一次：node tools/af_pipeline/LayerText_AF清单.mjs --reimport
或者明知在漂移仍按现场 CSV 跑：LAYERTEXT_LEXICON=live <原命令>（会在日志里留痕，产物口径自负）
代价（逐词）：已知词口径变了：正本 3315 个、现场 3316 个；现场多出 1 个（用正本跑，这些词不会被加注）：zzzverifyword
```

### 5.3 独立复核（我自己跑的，不是照抄子代理的结论）

| 步骤 | 结果 |
|---|---|
| ① 无正本 → legacy | exit 0 |
| ② `--new` 建正本 | 快照版本 `7f02a62f353e5085` **与既有一致**（没有凭空造一次"词表已变"） |
| ③ 有正本再跑同一条命令 | **两种模式的产物逐字节相同**（只差"生成时间"一行） |
| ④ 改 `词库.csv` | exit 1 拒绝，点名来源 + 两个哈希 + 逐词代价 + 修法 + 逃生门 |
| ⑤ `LAYERTEXT_LEXICON=live` | 按现场跑，且**正本一个字节都没动** |

### 5.4 「一处改动，15 个脚本一字未改」

六个 loader 全部改为"有正本读正本"。**向后兼容是硬约束**：
没有正本的项目，代码路径与改造前**逐字相同**，只在 stderr 说一行。

**刻意没修的两处既有缺陷**（已在代码里写明，不顺手"改干净"）：
`appendDict` 里 `loadKbGloss()` 历史就是无参调用（⇒ 词典 CSV 的「来源」列恒为「归一（多数票）」，
即使释义其实来自教师知识库）；`loadKnownForms` 会把内置词表里的 `#` 注释行读成一个词 `"#"`。
顺手"修干净"= 换掉一批词的判定，属于另一件事。

### 5.5 两处需要点头的判断

- **`--new` 顺带导入正本**：理由是"建清单"的语义就是"把这次的输入冻下来"，
  只冻指纹不冻数据，等于把"三天后有人改了词库"留到跑完才发现。
- **正本的出处不含「情节底线」**（而快照的 sources 含它）：
  改一句剧情底线不该拦下一次词表读取，那是假警报。
