# 功能四项 · 规划与验收标准（2026-09-19）

来源：09-19 Wayne 拍板"1234 先做验收标准然后再开始"（四项=层间体检进 App / 人话判读铺满 / FSRS 复现闭环 / 分档×考试回溯）。
方法沿用仓库惯例：每条标准机器可查（测试名、退出码或 grep）；未达标只准标"部分完成"并列阻塞项；每项独立提交、独立过 verify、写 CHANGELOG。

总门禁（每一项做完都要过）：`npm run verify` 全绿（当前基线 1109 项）；涉及 `app/` 另加 `cd app && npx vite build`；涉及仓外数据（项 4）另加"数据不进仓 + 产物无学生姓名"双查。

## 零、设计定案（先冻结，防走样）

1. **判定唯一实现（项 1）**：App 层间体检直接 runtime-import `src/core/acceptance.ts` 的
   `acceptanceV2`（词画卷先例），维度一个不自算；known 用 App 现场词表（`buildLexiconNow` 同口径），
   proper 用书配置专名表可缺省——缺了语义维度**显式"未算"**，不静默当零警报。
2. **判读=纯函数+出处（项 2）**：每条人话判读的阈值锚点必须来自项目**已定标**的数据——
   句长=贵阳中考 11 年定标（P50≈10、干净年 P90 17-20，LayerText_文档/句长定标_2026-09-16.md）、
   生词率=档位目标（≤2% 顺畅 / 2-5% 可读 / 5-10% 吃力 / >10% 读不下去，两轮调适制定标）、
   注密度=`ANNO_DENSITY_WARN=8`（v2.1）。**不许新造阈值**；判读不改指标本体，只成对随行显示；
   判读函数零 DOM（可单测）。
3. **FSRS 并行试点口径不变（项 3）**：`planFsrs` 的"FSRS 建议 vs 现行固定隔 2 篇"并排**不切换**——
   本周清单两列都给教师，FSRS 列标"试点参考"；**教师端 only**（无打卡、无提醒、无学生端界面）；
   出题选词从"队列前 30 个"升级为"FSRS 到期优先"；CLI `fsrs` 子命令行为零变化（前两列兼容已实测）。
4. **项 4 红线**：学生数据不进仓库；产物**零学生姓名**（只有梯队级聚合率）；脚本只读
   （成绩数据库与 AF 产物目录零写）；输入目录走环境变量；措辞守 exposure≠acquisition
   （考试词形产出≠习得；回溯只述相关不写因果）。
5. **结构纪律**：新文件同步 `docs/文件架构.md`（铁律 1）；App 模块撞 max-lines 1000 按先例拆分。
