### 3.3 单句改写这条路上，改造前真实存在的三个口子

`acceptSuggestion` 原来是"把内存里的整份稿写回去"。三个口子都被用例钉住了：

1. **采纳时不复判门禁**——判定发生在"生成候选"那一刻，写入发生在教师按键那一刻。"检查出错"原来会退回建议页（这一条旧代码是对的），但"生成时过了、采纳时未必还过"没人查。现在**写入这一刻重跑门禁**，且刻意**不**回退到缓存结论（`tests/adoptrewrite.test.ts` 第 4、5 条）。
2. **没有 `baseVersion`**——编辑器里有未保存改动、或别的窗口改过同一章时，整份覆盖会**顺手抹掉别人的改动**。现在先比对盘上与会话的内容哈希，不一致就拒绝并说明（第 7、8 条）。
3. **没有版本节点**——"这一段现在这样是哪来的"答不出来。现在每句采纳都出父版本 + 事件（第 1 条）。

### 3.4 顺带修掉的两个真缺陷

- **`applyAction` 的"哪个词"检查位置错了**：它原来放在所有分支之前，于是 `revert`（撤销）与 `rewrite`（单句采纳）这两个**不需要 word** 的动作一律被误判成 `missing-arg`。是 `adoptrewrite` 的用例当场抓到的（`src/core/riskaction.ts`）。

## 四、阶段 2 / 阶段 3：本轮修掉的**已实测缺陷**

### 4.1 阶段 2 —— 任务组**没有**达到压缩比（已修）

计划的验收是「对 Animal Farm A 层第一章，**70 条**原始问题至少压缩为不超过 **25 个任务组**」。
用真产物实测（`tests/fixtures/风险队列_A层85_70条.json`，就是从真项目拷进来的那一份）：

| | 组数 | 同词 | 同段规则 | 同章类型 | 单条成组 |
|---|---|---|---|---|---|
| 改造前 | **55** ❌ | 39 | 16 | **0（死代码）** | 46 |
| 改造后 | **19** ✅ | 3 | 13 | 3 | 0 |

根因是两处：44 条 `ANNO-01` 里 36 个词**只出现一次**，每个单例词各自成组；而本该兜底的 `chapter-category` 档被前一档的条件全部吃掉了，**永远走不到**（`GroupKind` 里声明了它，全仓却没有一处引用——一个写法上存在、运行时不存在的分支）。

改法：前两档的判据从"键相同"改成"**键真的聚起来了**"（词需 ≥2 次、段+规则需 ≥2 条），第三档变成全收兜底 → 组数天然 ≤ 条数，单章散项最多"章 × 类别"个组。`samples`（3 条代表样本）、排序、`uniformAction`（组内动作不一致禁止批量）全部原样保留。

顺带补上 **AC2**：`batchPreview(g)` 列出**将改动的词与段**（不再只有"改动 N 处"三个数），并修掉"没有批量按钮的组仍然显示『全部应用会改动 N 处』"这个**假承诺**。界面把它做成默认折叠的一节——不该抢注意力，但按按钮之前一定能打开看。

顺带修掉一条**名实不符的测试**：`tests/riskqueue.test.ts` 里名为「同章同类型的散项归一组（语言类）」的用例，断言的是 `kind === 'segment-rule'`。名字和断言互相矛盾，等于给一个死分支盖了张通行证。

### 4.2 阶段 3 —— 两处会**静默出错**的路径拼接（已修）

审查结论是：引擎层（`manifest` / `LexiconSnapshot` / `Resolver` / `decisiondb` / `withLock`）是真的且有用例，但**接线层没做完**——17 个脚本只有 4 个接了 `Resolver`。本轮只挑"会静默出错"的两处修：

**① `LayerText_AF会话改写.mjs` 的已注词账本绕过了 `Resolver`**

```js
// 改造前（第 654 行）——注意同一个文件第 670 行的产物路径是走 R.any('正文') 的
const p0 = join(OUT_BASE, `第${cn}章`, `原文_${TAG}_${DATE}${SUFFIX}.md`);
```

`--layout run` 下 `R.any('正文')` 指向 `_运行/<runId>/正文/…`，手拼的那条**永远不存在**：`existsSync` 全部 false → 账本一个词都读不回来 → **跨章去重静默失效 → 同一个词被反复加注**——而脚本照常报告成功。现在改走 `R.any('正文', { chapter })`（legacy 下逐字符等价）。

**② `清单_最新.json` 是一份**全局**指针，两个人并发跑会互相覆盖身份**

原来三个脚本 + App 面板各自写了一遍"读 `清单_最新.json` → 再读它指的那份清单"，读的是**同一个全局文件**。两位教师同时跑同一本书的不同层级时：后跑者覆盖先跑者 → 先跑者的进程接着去读到**对方的 `runId`** → 把产物写进对方的运行私有目录，而两边都报成功。**`--layout run` 挡不住这个**：它挡的是"路径撞名"，不是"身份被换掉"。

改法：
- 指针**按 (教师, 层级) 分片**（`pointerNameOf` → `清单_wayne_A层85.json`），每个身份一份，谁也覆盖不了谁；
- `清单_最新.json` 退化为**索引**（给人看的"最近跑过哪一次"），不再是任何程序的事实源；
- 四个消费方（三个脚本 + App 面板）统一走**一个**解析入口 `readRunIdentity`，判断逻辑在引擎的 `chooseIdentity`（纯函数，有单测），脚本只负责读盘；
- **对不上就拒绝借用**：只剩"最近一次"且它的教师或层级跟我对不上时，**不是**默默用别人的运行，而是退回 `legacy` 并把"我读到的不是我的运行"响亮地说出来，同时告诉人正确的并发姿势（`--run` / `LAYERTEXT_RUN`）；
- 坏指针**不许半途生效**：指针指向的清单读不到 → 整份指针视为读不到（半生效比彻底失效更危险，它会让人以为一切正常）。

证据：`tests/runidentity.test.ts`（14 条）+ `tests/pipeline_gate.test.ts` 新增一条"身份不明时拒绝借用别人的运行"（断言**一个字节都没写进别人的运行目录**）。既有的"两位教师各跑一次互不影响"那条也改成显式声明身份——因为**身份挂在共享可变物上，本身就是那个缺陷**。

### 4.3 本轮**自己引入**的缺口：账本追加不是原子的（已一并修掉）

新增的版本日志与已有的决定日志都是 append-only，但写入是"读全文 → 拼一行 → 写全文"。
两个人（或两个窗口）同时追加时，后写的那次会把前一次的整份内容覆盖掉——
**丢的是一整条决定或一整版记录，而且没有任何迹象**。这跟本项目一直在治的"静默坏产物"是同一类。

- Tauri 侧新增 `append_text_file`（`O_APPEND`）——内核语义是"写入时原子地把偏移推到文件末尾再写"，
  所以一次一行不会互相覆盖；账本行都很短，这是"不换存储引擎也能拿到的原子性"。
- 面板与单句采纳的 IO 都接上它（`app/src/main.ts`、`app/src/aiflow.ts`）。
- 面板同时补上了 `backup`：改正文之前先留一份"原始备份"，已有就不覆盖——
  从前这条退路只长在 `persistEdit` 上，走新事务的路径反而没有。

### 4.4 决定事件里的 `sourceVersion` 不再是层级标签

审查报告 A4 的结论是「数据存在但**源头就是错的**」：`app/src/main.ts` 给面板传的
`sourceVersion` 是 `A层85` 这类标签，而 `DecisionEvent.sourceVersion` 的定义是"产物版本标识（源文件哈希）"。
一个季度后再看，`A层85` 指向的那份稿早被改过很多次了。

现在面板在**入口处**把 `sourceVersion` 换成**这一轮队列产物的内容哈希**
（队列是教师这一轮实际在看的东西，整个会话里稳定；更精确的"哪一章的哪一版"
由版本节点的 `parentHash` / `contentHash` 回答）。换在入口而不是每个调用点，
是为了不让"有的决定有版本、有的没有"这种事发生。

**二、锁只护词典**（全仓 2 处调用，都在 `${P.词典路径}.lock`），清单/快照/指针/会话日志/正文**全无锁**；`withLock` 本身是"读-判-写"，存在竞态窗。原子写只有词典用了 `tmp + renameSync`；正文与会话日志是裸 `writeFileSync`。账本追加的原子性已修（§4.3），但**正文本身的并发写**仍无锁——两个人同时用同一份底稿改不同段时，乐观并发（`baseVersion`）会让**后者被拒**，不会写坏，但教师会看到"稿件已经改过，请重新出队"而不知道为什么。**这是下一个该修的。**

**三、默认布局仍是 `legacy`**。这不是漏做，是**不打算单方面改**：它会让教师已有的工作流换目录，而"不破坏教师已有工作流"是硬约束。正确做法是加一条显式的迁移步骤（`--layout run` 时先校验没有并发身份冲突），而不是把默认值翻过来。

**四、（已修，见 §4.4）** `sourceVersion` 在 App 面板那边原来还是层级标签。
