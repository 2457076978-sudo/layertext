## 零、设计定案（先冻结，防走样）

1. **golden 锁的是"尺子的代码"，不是"真项目的数"**——真项目会变（回放层哲学原文），所以锁分两层：
   仓内合成书 golden（CI 处处可跑，覆盖每个维度的触发形态）+ 回放夹具扩展（仓外、环境门控 t.skip，
   锁"报给教师的那些数"对夹具书的稳定性）。**两层都消费 `src/core/acceptance.ts` 唯一实现**，
   golden/回放不许自算维度（口径唯一）。
2. **golden 快照须逐条人工 review**（仓库既有承诺：记的是期望行为，不是现状捕捉）——golden
   首次冻结时逐字段人工过目，测试注释写明。
3. **反证是 golden 的验收**：临时改尺子（如 1.15 容差→1.2）必须红——不红的 golden 是空炮。
   反证过程留 CHANGELOG，红码不入库。
4. **注密度进 App 门禁是"警戒"不是"硬闸"**（v2.1 定位=独立指标）：超线 ⚠ 点名最差段、
   不拦终审勾选——教学决策留给教师；诗歌段豁免登记在管线侧，App 侧无注册表不装懂。
5. **重冻结是有意动作**：回放夹具 `期望结论.json` 加 v2 字段 = 一次显式 re-freeze（旧版备份同目录），
   不许顺手把红改绿。
6. **发版停在"本地就绪待推"**：版本收敛 + CHANGELOG 成段 + verify/USER=runner 双绿 +
   release-checklist 走查；tag 与 push 等 Wayne 发话（网络绕行+冻结惯例，列进发版闸门）。
