# LayerText 项目数据格式规范 v1

> 制定：2026-09-10｜适用：本工具及使用本工具的所有班级项目
> **本规范是"工具能给别人用"的地基**——数据格式不固定，脚本就只能作者自己跑。

---

## 〇、这份规范解决什么

三句话：

1. **同一件事只能有一个正本**，其余文件都是由它生成的（现在"分层"这件事同时存在于 3 个文件里，谁说了算没人知道）；
2. **什么内容用什么格式**，不许混（数据用 JSON/CSV，给人读的用 Markdown）；
3. **AI 填的数据必须能被确定性校验**，校验不过就报错重填。

第 3 条尤其重要——它和本项目在**文本**上的方法论是同一件事：

> 文本上你已经学会了"AI 生成 + 确定性检查"（三层把关）；
> **数据上同理**：不能因为是大模型填的就直接信。

---

## 一、两条轨道：谁产生数据，决定用什么格式

| 轨道 | 数据 | 格式 | 谁产生 | 为什么 |
|---|---|---|---|---|
| **A. AI 填** | 分层参数、书级知识库、专名表、注释词典、画像元数据 | **JSON** | 云端 API（老师引导） | 大模型生成 JSON 最稳；可强校验；多数 API 有结构化输出模式 |
| **B. 机器转** | 词库、画像逐生数据 | **CSV** | 脚本（从原始成绩/教材表转换） | 数据量大、逐行，**绝不能由 AI 编造** |

### 为什么不用 Markdown 存数据

Markdown 表格是**排版格式，不是数据格式**：没有转义标准（内容里有 `|` 怎么办）、没有类型（分不清 `3` 是数字还是字符串）、diff 噪声大（改一个字段整表重排）、工具生态差。**给人读的用 Markdown，给机器读写的用 JSON/CSV。**

### 三条已定决策（2026-09-10 拍板）

| 决策 | 选定 | 理由 |
|---|---|---|
| 字段命名语言 | **中文键** | App 与现有文件已如此使用，改动成本高；使用者是中国教师，中文更可读 |
| 版本管理 | **文件名不带版本号**，版本写在 `_meta.版本` | 脚本路径稳定，不必随版本改 |
| 数据正本数 | **每个对象只有一个正本**，其余为派生 | 消除"三处描述同一件事" |

## 二、六个数据对象

### 2.1 词库（学生已知词）· CSV · 轨道 B

> **作用**：判定"学生学过没有"的**唯一锚**。文本简化的一切词汇边界都由它决定。

| 字段 | 必填 | 说明 |
|---|---|---|
| 词 | ✅ | 单词或短语（短语整词保留，如 `bring about`） |
| 类型 | ✅ | `单词` / `短语` / `句型` |
| 词性 | | `n.` `v.` `adj.` `phr.` 等 |
| 释义 | | 中文释义 |
| 来源册 | ✅ | 教材册次（如 `九上`）或 `课标1600` |
| 来源单元 | | 单元号（如 `U1`） |
| 音标 | | |
| 备注 | | |

**`类型` 的 5 个取值**（实测自 v0.6；⚠️ 这个字段有语义，不只是标签）：

| 值 | 条数 | 含义 | 对"已知"判定的影响 |
|---|---:|---|---|
| `单词` | 1635 | 教材词（八上/八下/九上单元词） | 计为已知 |
| `课标词` | 1468 | 来自课标 2022 三级词表 | 计为已知 |
| `短语` | 503 | 短语，整词保留不拆分 | 计为已知 |
| `句型` | 139 | 句型/句式 | 计为已知 |
| **`待定词`** | **194** | **AI 补词中尚未通过独立核对者** | ⚠️ **口径可变！** |

**⚠️ 关于 `待定词` —— 口径已定，但必须写下来（2026-09-10 查明）**

这 194 条是"非课标三级词、来源待证"的词。**引擎的既有判据**（`src/core/lexicon.ts` `loadVocabCsvText`）是：

```js
if (t === '单词' || t === '课标词' || t === '待定词') {
  known.add(w);                      // 待定词算「已知」（宽松口径）
  if (t === '待定词') pending.add(w); // 但同时记入 pending 风险标记
}
```

即：**待定词计入已知**，同时引擎另用 `pending` 集合在报告里输出"⑨待定词 token 命中（保守口径风险）"。

| 口径 | 覆盖率 | 说明 |
|---|---|---|
| **现行（宽松）** | 99.7–100% | 待定词算已知 —— **引擎当前行为** |
| 保守 | B 97.7% / M 98.0% / A 98.2% | 待定词算未知，差 1.7–2.3 个百分点 |

**两条规则**：
1. **不得擅自改动此判据**——改了会动所有已报数字（三档汇总、台账、论文数据）；
2. **任何引用生词率的报告必须声明口径**。这是本项目已知的口径风险点。

另注：`短语` 与 `句型` **不计入 known**（引擎 token 级匹配用不到多词短语，属有意设计，非缺陷）。

**红线**：词库**只能来自权威来源**（课标词表、教材词表）。**AI 补的词必须核对后才能入库**——本项目曾把 133 个词误标，教训在 `知识文件/AI补词核对_v0.1.csv`。

**判定的坑（务必写进任何使用者文档）**：判定"已学"要用 **课标1600表 ∪ 词库**，不能只用词库（词库的课标子集曾漏收 300 来个课标词，导致 `pig`/`man`/`sheep` 被判成生词并被加注）。且要做**词形归并**（`running→run`、`cried→cry`），用**正向生成变形**而非反向剥后缀（反向剥会把 `hissing` 认成 `his`）。

### 2.2 分层与调适参数（组级）· JSON · 轨道 A

> **作用**：**组级参数的单一正本**。App 的分组配置、Markdown 参数表都由它派生。

```json
{
  "_meta": {
    "schema版本": "1",
    "数据版本": "v1",
    "名称": "示例班·2026秋",
    "生成": "2026-09-10（画像_分组导出.py）",
    "口径": "组级参数，由 画像_<班级>.json 聚类结果折算",
    "红线": "含学生信息，只存本地，不进公开仓"
  },
  "groups": [
    {
      "id": "组:A",
      "名称": "A层(33人)",
      "类型": "组",
      "成员数": 33,
      "句长上限": 20,
      "覆盖目标": 95,
      "生词率上限": 3,
      "支架密度": "中",
      "已学词": [],
      "到期词": []
    }
  ]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | 唯一标识，`组:X` 或 `人:姓名` |
| `名称` | ✅ | 显示名 |
| `类型` | ✅ | `组` / `人` |
| `成员数` | 组必填 | 组内人数。**「人」类型条目没有此字段**（2026-09-10 依实测修正） |
| `句长上限` | ✅ | 单句英文词数上限（A20 / M16 / B14） |
| `覆盖目标` | ✅ | 词表覆盖率目标百分数 |
| `生词率上限` | | 超纲词比例上限 |
| `支架密度` | | `中` / `密` / `重` |
| `已学词` | | 该组额外已学词（叠加进词库判定） |
| `到期词` | | 复现队列到期词（注入下次生成） |

### 2.3 学习者画像（逐生）· JSON · 轨道 B

> **作用**：逐生证据。组级参数（2.2）由它折算。

```json
{
  "_meta": {
    "schema版本": "1",
    "数据版本": "v1",
    "名称": "班级画像（示例班）",
    "生成": "2026-09-08",
    "口径": "域级得分率=六次考试分值加权（近三次×2）",
    "红线": "含学生真实数据，只存本地，绝不进入公开仓"
  },
  "students": [
    {
      "姓名": "…",
      "现班级": "示例班",
      "层": "A",
      "层级参数": { "句长上限": "18-20", "生词率上限": "3%" },
      "六次均分率": "87.0",
      "域级得分率": { "识别": 91.6, "听写": 91.7, "整句": 85.9, "词形": 87.2 },
      "已学词集": { "link": { "source": "confirmed", "since": "2026-09-08", "hits": 0 } },
      "复现队列": []
    }
  ]
}
```

**关键约定**：`students` 是**数组**（不是以姓名为键的对象），保证顺序稳定、便于 JSON Schema 校验。

`已学词集` 里每个词的 `source` 三层状态（沿用 2026-09-08 已定口径）：
`auto`（读完第 N 章默认学会）→ `confirmed`（小测/听写证实）→ 毕业（复现满 3 次）。

### 2.4 书级知识库 · CSV · 轨道 A

> **作用**：**每本书一份**。教师确认的加注词与换词倾向，注入生成提示词。
> ⚠️ 现状：这份文件的路径**硬编码在 `LayerText_AF三档生成.mjs` 里**，必须抽成配置。

| 字段 | 必填 | 说明 |
|---|---|---|
| 类型 | ✅ | `加注词` / `换词倾向` |
| 词 | ✅ | 英文词（小写） |
| 值 | ✅ | 加注词的释义；换词倾向留空。**值若为流程标记（`复现`/`复数`/`比较级`）则不是释义，脚本应过滤** |
| 来源数 | | 教师确认次数，用于排序取 top |

---

### 2.5 注释词典 · CSV · 轨道 A

> **作用**：跨章**同词同义的正本**。杜绝同一词在不同章出现不同中文（修复前有 223 个词型一词多义，如 `squealer` 被注成"尖叫者/吱嘎/告密者/吱吱"）。

| 字段 | 必填 | 说明 |
|---|---|---|
| 词 | ✅ | 小写 |
| 释义 | ✅ | 中文，2–6 字 |
| 来源 | ✅ | `教师知识库` / `归一（多数票）` |

**生成流程**：先查本词典；词典没有的词才问模型；新词**回写词典**。

---

### 2.6 专名表 · TXT · 轨道 A

> **作用**：人名/地名/作品名。QC 不计生词，改写不加注。
> ⚠️ 现状：写死在 3 个脚本的 `PROPER` 常量里；且曾漏掉 `clover`/`squealer`/`mollie` 三个主要人物，导致 Clover 被注成"三叶草"、Squealer 注出四种意思。

**格式**：纯文本，一行一名，小写，多词名用空格（如 `animal farm`）。**每本书一份**。

## 三、⚠️ 冻结清单（改动即全盘失效）

以下格式**一旦定下就不许改**，因为它已被解析器依赖：

| # | 冻结项 | 格式 | 依赖它的东西 |
|---|---|---|---|
| 1 | **内联加注** | `word（中文）` | 全部解析、台账、加注统计、App 标注渲染 |
| 2 | 加注括号 | **全角** `（）`；词与括号**无空格** | 正则 `([A-Za-z][A-Za-z'-]*)（([^（）]{1,24})）` |
| 3 | **段落标记** | `[P##]` 行首、两位数字、连续 | 段落对齐、App 稳定锚、逐句台账 |
| 4 | 章标题 | `## Chapter N` | 引擎 `splitChapter` |
| 5 | 词句卡分节 | `## 词句卡` | 词数统计的截断点 |
| 6 | 专名表 | 小写、一行一名 | 生词率口径 |
| 7 | 注释词典 | 一个词**只允许一个**释义 | 跨章一致性校验 |

**注意第 1 条**：`word（中文）` 是**产品的一部分**（学生要能直接看懂），所以它既是交付格式也是解析格式。谁把它改成 `word(中文)` 或加空格，全项目解析立刻坏掉。

```
                                ├──► 覆盖率/生词率报告（Markdown）

专名_<书名>.txt   ──┼──► QC 口径（不计生词）
词典_<书名>.csv   ──┴──► 加注释义 + 新词回写

```

**规则**：派生文件**标"只读，勿手改"**，改了下次生成会被覆盖。

## 五、校验闭环（AI 填的数据必须过闸）

因为数据由云端 API 填写，**一定有"看起来对但解析不了"的情况**。所以：

```
① 我们发模板（含字段说明 + 示例）
      ↓
② AI 按格式填写 → 产出文件
      ↓
③ 跑 `node tools/validate_data.mjs <文件>`     ← 确定性检查
      ↓
   通过 → 进入识别与简化管线
   不通过 → 输出具体错误（哪个字段、期望什么）→ 回 ② 让 AI 重填
```

**校验项**（按对象）：

- **通用**：文件存在、可解析、`_meta.schema版本` 匹配、必填字段齐全
- **词库**：词为非空字符串、无重复、`来源册` 在允许集合内
- **分层**：`id` 唯一、`句长上限` 为正整数、`类型` ∈ {组,人}、`成员数` 为正整数
- **画像**：`students` 为数组、每生 `层` ∈ {A,M,B}、`域级得分率` 各值为数字
- **知识库/词典**：`类型` ∈ 允许集合、词小写、**词典无同词多义**
- **专名**：一行一词、小写、无空行

**这就是把"三层把关"从文本搬到数据上**：AI 生成 → 确定性校验 → （不通过时）人工或重填。

**校验器**：`tools/validate_data.mjs`（2026-09-10 已实现）
```bash
node tools/validate_data.mjs <文件或目录> [--all] [--json]
# 退出码 0=通过 1=有问题 2=用法错误；--json 供 AI 读取后自行修正
```

## 八、App「数据」面板（已实现）

**背景**：数据文件是正本，但**教师不应该用手改文件**——改错一个字符就会静默破坏整条链。
所以 App 需要一个「数据」区域：**看得见、能增删、写回时自动过校验**。

### 三条入口，同一份文件

```
① 脚本生成（画像 / 分层 / 词库）──────┐
② 云端 AI 填模板（知识库 / 专名 / 词典）─┼─► 校验 ─► 文件（正本）◄─► App「数据」面板
③ 教师在 App 里增删 ───────────────┘
```

三条路都必须过同一个校验器——**App 的写路径不允许绕过校验**，否则 App 会成为新的污染源。

### 面板要有什么

| 区域 | 显示 | 可做的操作 |
|---|---|---|
| **词库** | 词 / 类型 / 释义 / 来源册 | 搜索、新增、改释义、改类型 |
| **分层** | 组列表（成员数 / 句长上限 / 覆盖目标） | 改参数；改后一键重算派生文件 |
| **知识库** | 加注词 + 换词倾向 | 新增、改释义、删除 |
| **词典** | 词 → 释义 | 新增、改释义（**唯一性由校验器强制**） |
| **专名** | 一行一名 | 增删 |
| **状态条** | 上次校验结果 | 手动重新校验、错误定位 |

### 关键约束

1. **写前校验、写后校验**：每次保存都跑等价于 `validate_data.mjs` 的检查；不通过就拒绝写入并指出字段；
2. **正本 vs 派生要区分显示**：派生的文件（App 配置、Markdown 参数表）在界面上**标灰只读**，并注明"由 X 生成"；
3. **改动留痕**：每次编辑追加一行变更日志（沿用项目"改必登记"铁律）；
4. **学生数据不外传**：`画像`/`分层` 面板只在本机读写。

## 九、教材单元知识库与进度换算（2026-09-10 新增）

**要解决的问题**：教师说"我教人教版，上到八下 Unit 5"时，系统要能**自动算出哪些词学生学过**，
而不是靠人工维护一份词表。这个结果直接进生成提示词与 QC 口径。

### 9.1 教材单元知识库 · JSON · 轨道 B（由词库抽取）

```json
{
 "_meta": { "schema版本":"1", "数据版本":"v1", "名称":"人教版（新教材）教材单元知识库",
            "基础层":["课标1600","课标补丁"], "覆盖":["八上","八下","九上"] },
 "base": ["about","above","…"],
 "books": {
   "八下": { "U1": ["…"], "U2": ["…"] }
 }
}
```

- `base`：无单元信息的**基础层**（课标1600 + 补丁）——**永远算已学**，充当 七上/七下 的代理
- `books`：册 → 单元 → 词表（小写）
- 数据源：词库 CSV 的 `来源册` / `来源单元` 两列（多值用「；」分隔）

**覆盖现状（2026-09-10 实测）**：

| 册 | 单元级词汇 | 说明 |
|---|---|---|
| 七上 / 七下 | ❌ **缺** | 由 `base`（课标1600）代理 |
| 八上 / 八下 / 九上 | ✅ U1–U8 齐全 | 词库自带 |
| 九下 | ❌ **缺** | 初三下学期才用；需另行补录 |

### 9.2 进度换算

```bash
# 抽取教材单元知识库（从词库）
node tools/textbook_units.mjs build <词库.csv> --out 教材单元_人教版.json

# 说"上到八下 U5" → 产出已学词表
node tools/textbook_units.mjs progress 教材单元_人教版.json --at "八下:U5" --out 已学词.txt

# 单元只学了一半（如九上 U3 上到一半）
node tools/textbook_units.mjs progress 教材单元_人教版.json --at "九上:U3" --half --out 已学词.txt
```

**换算规则**：`已学 = base ∪ 进度之前所有册全部单元 ∪ 当前册进度之前的单元 ∪ 当前单元（--half 时取一半）`

实测（2026-09-10）：
- `--at "八下:U5"` → **3102 词**
- `--at "九上:U3" --half` → **3408 词**

**产出用途**：既可作为 `--wordlist`（QC 已知词口径），也可作为 `--reinforce`（复现队列），
或直接粘进 AI 改写提示词的"学生已学词"段。
