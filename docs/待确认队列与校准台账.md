# 待确认队列与校准台账

> 2026-09-13 落地。一句话：**机器算出来的"该看的地方"合成一张表，教师点过的决定不再因为换了一版产物就消失。**
>
> 与 [段级门禁与风险队列](段级门禁与风险队列.md) 是同一套哲学的两半：那里管的是**段落**该不该放行，
> 这里管的是**词/句**该不该加注、该不该换写，以及教师点过的那些决定存在哪里。

## 一、为什么改（查出来的真事故）

### 事故一：候选项做出来了，教师看不见

到 2026-09-13，机器能算出来的"该看的地方"散在两份 JSON 里，各有各的格式、各有各的口径：

| 来源                                | 规模（Animal Farm 全书） | 判据                                         | 谁看                   |
| ----------------------------------- | -----------------------: | -------------------------------------------- | ---------------------- |
| 未支持难词（补注候选）              |                   875 处 | 词在学生已知词库外、又没拿到注释支持         | 补注 / 换写 / 说明保留 |
| 正本核对                            |                  4049 处 | **教师自己定过的词**在产物里没了（判据最硬） | 保留加注 / 确认替换    |
| 引擎客观项（句长 / OOV / 中文残留） |                 每章若干 | 判定线                                       | 改稿                   |

教师在第一版里要打开两个视图、对两份 JSON 才能看全。现在合成 `待确认队列_<层>.json` 一张表，
App 里两个入口：「检 → 待确认」整章列表，以及右栏顶部常驻的「待确认 N 条 ▸ 去看」横幅——
**打开一章就看得见**（看不见＝等于没做，这是上一版的教训）。

### 事故二：教师点过的确认，换一版就"没了"

`_审校标记.json` 是**按文件名**落盘的，而管线每重新生成一版产物就换一个文件名：

```
原文_A层85_2026-09-10_审校标记.json           1 条（pellets / 词汇简化，教师 09-10 点的）
原文_A层85_2026-09-12_工序化_审校标记.json     0 条（教师后来打开的是这一版，读的是它自己那张空表）
```

校准没丢，它躺在**旧文件名**名下。全书十章里只有第一章留下过标记文件，其余九章一个都没有——
同一个根因的另一面。**其余九章的历史校准已无从补回**，只能在 App 里重新过一遍。

## 二、待确认队列：三路合成一张

纯逻辑在 `src/core/pendingqueue.ts`（不读盘、不写文件，可单测）。

**哪些引擎项并、哪些不并**（`ENGINE_OBJECTIVE_RULES`）：只并**机器确定**的 blocker——
`SENT-01` 超长句、`ANNO-01` 超纲词漏注、`ZH-01` 正文混入中文、`LEN-01` 篇幅偏离。
`FACT-01/02`（数字、专名在改写里找不到）与 `ANNO-02/03` **刻意不并**：改写可能合法地换说法，
机器判不准，那是"按风险排队等人工权衡"的活，留在风险队列按 `风险 = 概率 × 后果` 排序才有意义。
并进来只会让教师在一张表里分不清"必须改"和"可能要改"。

引擎项在面板里**不硬塞三个键**：段级的判断（超长句、篇幅）给的是「去风险队列处理 →」＋「③ 忽略」，
因为"补注 / 换成某个词"在那几条上根本不成立——给不成立的按钮比不给更坏。

### 两条纪律

1. **层的写法必须统一。** 补注队列写 `A层85`，正本核对写 `A`——不归一的后果是"同一个词在两份
   队列里算两件事"，教师点两遍、台账记两条，而人以为只点了一次。`normalizeTier` 负责归一。
2. **已决定的条目合并时要留住。** 队列可以随时重算，但教师点过的决定不能因为"重算"就消失：
   按**稳定 ID** 把 `status` / `decidedAt` 带过来。

### 稳定 ID 不含 kind

```
id = hash(层 | 章 | 段 | 词小写)
```

**刻意不含 kind**：同一个词在同一段里被两路口径同时点中（既在未支持难词里，又命中正本词消失）
是完全可能的——词库与词典本来就是两个集合。ID 里带 kind 就会变成两张卡、教师点两遍、
台账记两条，而他自己以为只处理了一处。合成一条后按**更强的判据**呈现（正本 > 补注），
两个理由都留着（`why` 用 `｜` 串起来）。

### 排序与筛选

排序：★加注词 → 引擎客观项 → 正本 → 补注；同档按章、段。教师从上往下扫，先看判据最硬的。
筛选用按钮（全部 / ★加注词 / 引擎 / 正本 / 补注 / **跨章复现** / **仅本章**），计数实时；
**默认显示全部**——默认藏东西是把"看不见"换个花样犯。

### 大章细分与跨章汇总（2026-09-13 补）

第八章一次 214 条，只按判据分档还是会淹没在同一个词里。两件补强：

- **跨章复现**：判据是这个词出现在**几章**（不是几段）。`comrades` 在 6 个段落全丢不是 6 次手滑，
  是**一条口径问题**——处理一条顶一批。行上直接标 `×N 章`。
- **词频优先**：按词频排序，跨章复现最多的排最前，同频回落到判据强弱。
- **跨章汇总**：面板顶上一行「全书 N 条待确认 · 已处理 · 共 · 还有几章没清完」＋各章待确认条数
  （当前章高亮）。看不到"全书还剩多少、哪章最多"，就只能一章一章地猜。

### 批量处理

「批量（对当前筛选出的 N 条）」提供**全部 ① 补注 / 全部 ③ 忽略**（★114 条判据最硬，
不必一条条点）。三条纪律：只处理**当前筛选出来的**（教师看到的范围就是批量的范围）、
**必须显式确认**、**只打标记不写正文**（正文仍要点「按标记修改」才写入——这也是它敢一次批量的前提）。

## 三、三个键：每个键都有明确的传播口径

| 键       | 做什么                         | 落什么                                                  | 向不向下层传播                                                                 |
| -------- | ------------------------------ | ------------------------------------------------------- | ------------------------------------------------------------------------------ |
| ① 补注   | 保留原词，给它加中文注释       | `zh` 标记（正文先打标记，点「按标记修改」才写入）+ 台账 | **传播**（`annotate`，直接落实到下级文本）                                     |
| ② 换成 X | 填你想换成的词                 | `simpl` 标记 + 台账                                     | 只写下级待办（`rewrite`，不直接改下级正文）                                    |
| ③ 忽略   | 不注也不换，只记一笔"我看过了" | 台账 + 队列 `status`                                    | **不传播**（上级觉得不用管，不等于下级也觉得不用管——三层的学生词库本来就不同） |

两个刻意的设计：

- **③ 只记决定，不产生任何标记。** 写成标记的后果是 AI 审核建议流程会把它当待办，拿"这个词忽略"
  去问一次 AI、产出一条空建议，再被引擎复核报"仍含超长"——一条"什么都不做"的决定凭空长出一串动作。
  它要的两件事（留审计、下次别再问）分别由台账和队列 `status` 兜住。
- **② 教师亲手填的词不再经过 AI。** 见下节。
- **② 有明确的"谁执行"。** 点 ② 确定后决定立刻落成 `simpl` 标记——**标记清单就是换词队列**。
  面板顶上会多出一条「换词待执行：N 个词 ▸ 现在就换」，点它就地执行（词级替换、句子其余部分逐字不动、
  可撤销）。此前这一步靠教师自己想起来去工具栏点「按标记修改」，想不起来就等于没排。

## 四、教师指定的替换词：人定的东西不能被机器覆盖

教师在 ② 里填了替换词，意思是"就换这个"。但原有的「词汇简化」流程是把所有标记词**再问一次 AI**，
结果是教师填的词被静默丢掉、AI 换一个别的。现在：

- 标记备注写成固定格式 `教师指定替换：X → Y`；
- `pipew.ts` 读到这个前缀就**直接采用**，该词**不进 AI 输入**；
- 同词冲突时**以人为准**（教师口径优先于词典与模型候选）。

解析函数 `parseSpecifiedReplacement` 与写入端共用同一个常量 `SPECIFIED_REPLACEMENT_PREFIX`，
两边不可能再写岔。

## 四之二、换词队列：② 之后谁执行

教师点 ②（换成 X）时，App 做两件事：**记台账**（`source: human`）＋ **落一条 `simpl` 标记**。
标记清单本身就是换词队列；缺的只是"看得见 + 一键执行"。所以「检 → 待确认」面板顶上有一条：

```
换词待执行：N 个词（M 条标记，其中 K 条是你亲手指定的词——不会再问 AI）
② 填过"换成 ___"的词都排在这里；执行后正文就地换掉，可撤销。            [现在就换]
```

点「现在就换」调用既有的换词管线（`applyWordSimplifications`）：**教师指定的词直接采用、
不进 AI 输入**，其余的词才交给模型找课标内简单词。词级替换、句子其余部分逐字不动、可撤销。

执行失败**会说出口**（状态栏），不会静默回到"自己去工具栏找按钮"。

## 五、校准台账：事件是正本，标记文件是视图

| 东西                   | 角色                        | 挂在什么上             | 换版本         |
| ---------------------- | --------------------------- | ---------------------- | -------------- |
| `_审校标记.json`       | **视图**（供 App 快速渲染） | 文件名                 | 失效，可重建   |
| `_运行/校准台账.jsonl` | **正本**（append-only）     | 书 + 章 + 层 + 词/句锚 | **重放得回来** |

纯逻辑在 `src/core/calibration.ts`。三条纪律：

- **只追加，不改写历史**（与 `decision.ts` 的 `_决定/<层>.jsonl` 同一条哲学）；
- **来源分得开**：`source: human`（教师点的）与 `ai`（模型提的候选）一眼可辨——
  论文里"人工校准"是可审计的教师判断，模型候选只是建议，混在一起事后没人能回答"这条到底谁定的"；
- **找不到锚的事件如实报**，不许静默少给（`--replay` 会列出来）。

App 侧在打开一章时自动重放：`addSession` 调用 `replayInto`，把台账里属于 书/章/层 的过往校准
重新定位到**当前这一版**的正文上。台账坏了不拦人打开文件（与"账坏不能把活干坏"同口径），
只在 console 留一条警告。

### 与 `_决定/<层>.jsonl` 的分工

|        | 校准台账                      | 决定日志                           |
| ------ | ----------------------------- | ---------------------------------- |
| 模块   | `src/core/calibration.ts`     | `src/core/decision.ts`             |
| 管什么 | 审校工作台上的**词/句级**校准 | **风险队列**上的采纳 / 退回 / 误报 |
| 粒度   | 词、短语、句                  | 风险队列项（`itemId`）             |

两者都是不可变事件，都**不写正本词库**——入库那一步永远留给教师显式确认。

## 五之二、台账的三个出口（2026-09-13 接通）

台账是论文素材的来源，但它落在 `<产物目录>/_运行/`，不在数据面板列的那几个资产文件里——
不接出去就等于只有命令行看得见。三个出口各管一件事：

| 出口               | 带上什么                                                                                        | 在哪看                                               |
| ------------------ | ----------------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| **数据面板**（库） | 台账卡：总数、教师亲判/模型候选、覆盖章数、类型分布、各章条数、最近 5 条、坏行数                | App →「库」页顶部；含「在访达中显示」「复制路径」    |
| **审校档案**       | 单章档案多一节「人工校准台账（本章，教师对词/句的判断）」；面板上多一行计数                     | App →「检 → 档案」；导出本章 / 全书档案的 md 都带    |
| **发布包**         | 台账文件本身进清单（所以进包）＋ 包描述里的 `calibrationCount` ＋ 溯源 `--where` 新增一张校准表 | `LayerText_AF发布包.mjs --export` / `--where <文件>` |

三处都遵守同一条纪律：**读不到就如实说读不到，不按 0 处理**——坏行数会显示在卡片上，
包描述里 `calibrationCount` 与 `decisionCount` **分开记**（两本账：那边是风险队列项的采纳/退回，
这边是审校工作台上的词/句级校准）。

## 六、怎么跑

```bash
# 1) 教师词典/知识库登记过、产物里却消失的词（判据最硬的那一批）
node tools/af_pipeline/LayerText_AF正本核对.mjs

# 2) 未支持难词 + 本地模型带句填的中文候选
node tools/af_pipeline/LayerText_AF补注候选.mjs

# 3) 合成待确认队列（App「检 → 待确认」读它）
node tools/af_pipeline/LayerText_AF待确认队列.mjs            # 三层都生成
node tools/af_pipeline/LayerText_AF待确认队列.mjs --tier A   # 只生成 A 层
node tools/af_pipeline/LayerText_AF待确认队列.mjs --no-canon # 不要正本那一批

# 4) 台账：把历史标记文件导进正本，看概览，或预演重放
node tools/af_pipeline/LayerText_AF校准台账.mjs --import
node tools/af_pipeline/LayerText_AF校准台账.mjs --status
node tools/af_pipeline/LayerText_AF校准台账.mjs --replay <某版正文.md>
```

产物落在 `<产物目录>/_运行/`：`待确认队列_<层>.json`、`校准台账.jsonl`、
`正本核对_<日期>.json`、`补注候选_<层>.json`。

## 七、本地模型的边界（实测，写死在代码里）

`LayerText_AF本地助手.mjs` 用本机小模型（oMLX 上的 MiniCPM5-2B），但**只**用在实测扛得住的地方。
2026-09-13 实测（过程见 `Desktop/LayerText_本地裁判_试验/`）：

- 同一个 2B 模型，**1 段输入**能报对问题、**2 段起就一条不报**；
- 让它补全空字段会**直接编**；
- 让它给段落分类会**一律答"叙述"**；
- 让它判卷能挑出错，但**给分不可信**。

结论——**输入短 + 任务单一 + 判据明确 + 输出可机检**，四条同时成立才用它，缺一条就交回
确定性脚本或人。所以它只做两件真在调模型的事：**带句释词**（实测 4/5 正确，与项目词典对账，
一致/不一致都如实说）与**句级拆句**（不是段级——段级实测会把整段抄回原文）。

**这条边界已经接进 App**（2026-09-13，可选、默认关）：AI 设置里的「启用辅助模型」把本机端点
（默认 `http://127.0.0.1:8000/v1` + `Ling-3.0-tiny-oQ4e`）填上，App 就把**词汇简化**与
**短语注释**这两条映射类小活交给它——判据 `auxReady` / `auxSuitedFor`（`src/core/aiops.ts`，
App 与管线共用一份），上限 `AUX_MAX_WORDS = 12` 且**超限整批退主模型、不拆批**；辅助模型
失败/超时自动回主模型并在状态行说明原因；输出仍过同一套机检。整章简化 / 逐句改写 / 对话
**一律仍走主模型**。
「出选项卡」与「CSV↔JSON 格式转换」走确定性模板：任何模型做格式转换都是负收益——
慢、贵、会被 max_tokens 截断，而且逐字复制上千行它必然抄错，`writeFileSync` 一行就干完且 100% 可复现。

## 八、如实记录的遗留

- **其余九章的历史校准补不回来**（当时没落盘），只能在 App 里重新过一遍；
- **第十章语料残缺**（原文与三层产物都只有 3 段，断点还有词表碎片）——这是生成管线那边的账；
- 正本核对 4049 处里，绝大部分是**跨章复现**（同一个词在多章一起丢），属口径问题而非手滑：
  逐条处理性价比低，建议按"跨章复现"聚合后再过。
