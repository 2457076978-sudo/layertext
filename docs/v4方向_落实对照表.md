# v4 方向落实对照表（《LayerText 审查报告 v4_方向》 → 实现 → 证据）

> 逐条把 v4 报告的建议映射到**代码位置**与**验证方式**。
> 判定口径同上一份：**有实现 + 有自动化断言 + 在真项目上跑过**，三者齐才写 ✅。
>
> 复核：`npm run verify`（typecheck 引擎+App · lint · **495 项测试**全绿）；
> `HEAD = d34884a`，自上一份对照表以来 6 个提交。

## 先认一句账

v4 报告点出的**系统性偏差**成立：「你确实有『不断加工程保险、回避产品承诺』的倾向：
manifest、AST、事件账本都必要，但它们**不能替代一次成功的编辑闭环**。」

前几批（第二十六、二十七批）做的全是"让机器别出错"——门禁、清单、AST、并发安全。
v4 之后的六批里，**只有第三十一批在量教师那一侧的结果**，其余五批是把**编辑闭环**补齐。
这个比例本身也说明那份批评是对的。

## 一、只能做三件事

### 1. 统一的 SentenceRewrite 服务契约

| 报告要求 | 实现 | 证据 |
|---|---|---|
| ✅ App 与管线共用同一个输入输出 schema、同一个 `gateSegment` 判定 | `src/core/rewrite.ts`（`RewriteRequest` / `RewriteResult` / `checkRewrite`） | `tests/rewrite.test.ts` 第 1 条：结论与直接调 `gateSegment` **逐字段一致** |
| ✅ 合并契约与门禁、分离上下文与成本；App 只传局部切片 | `fullPolicy`（管线）/ `policySlice`（App，只带专名 + 本句命中释义 + 已注词账本） | `tests/rewrite.test.ts` 第 17–20 条；`tests/rewritegate.test.ts`（10） |
| ✅ 不通过门禁就不能直写正文，只显示候选与失败原因 | `app/src/aiflow.ts` 的 `gateRewriteCandidate`；**连"标记即改写"（原本直写）也不放行** | `tests/rewritegate.test.ts` 端到端两条 |
| ✅（外加）策略缺什么要**可见地缺** | `missingPolicy` + 界面徽标三态 | `tests/rewrite.test.ts` 第 13–15 条 |
| ✅（外加）门禁自身出错**不允许变成放行** | `aiflow.ts` 的 catch 分支退回建议页 | 代码注释与 `gateBadge` 用例 |

**与报告的一处有意差异（写在类型注释里并用断言锁定）**：单句 scope 只查「**这次改写新引入的**超纲词」。
源句本就该注而没注的是**补注脚本**的活；算在单句改写头上会让老师每改一句都被要求顺手加注。

### 2. 风险决定＝「动作 + 事件」事务

| 报告要求 | 实现 | 证据 |
|---|---|---|
| ✅ 「采纳」拆成规则特定动作 | `src/core/riskaction.ts` 的 `actionOf`：事实/长度类「认可」（不改正文）、漏注「＋ 补上注释」、重复注「－ 删掉多余注释」、释义冲突「＝ 改为词典释义」、无确定性修法的一律 `manual` | `tests/riskaction.test.ts` 第 1–3 条（**十条规则不许共用一个「采纳」**） |
| ✅ 先校验当前位置仍等于 before | `applyAction` 在读盘后的**最新**正文上找段/词；找不到就是 `not-found` | `tests/riskaction.test.ts` 第 6、9 条 |
| ✅ 原子写正文与事件 | 次序统一为「内存里跑完 → 写正文 → 写事件」，**事件写失败回滚正文** | `tests/riskpanel_dom.test.js` 第 15 条（模拟日志写失败，断言正文被改回原样） |
| ✅ 失败只写 `rejected` 且**卡片不得消失** | 新增 `rejected` 决定类型；`isResolved` **不把它算作已处理** | `tests/riskpanel.test.js` 两条；`tests/riskpanel_dom.test.js` 失败路径一条 |
| ✅ 撤销是 `undoOf` 新事件，不是删历史 | `undo` 类型 + `undoOf` 指针；`latestDecisions` 忽略 undo | `tests/riskpanel.test.js` 撤销三条 |
| ✅ 面板要有「看我判过的」入口 | `decidedRows` + 折叠区 + 逐条撤销键 | `tests/riskpanel.test.js` 第 2 条 |

**撤销语义定死为单级**（报告没说撤到哪一层）：撤销最新那条 = 整条作废、回到待办。
理由是界面上撤销键长在最新那条上，多级回退会让"现在到底算什么状态"说不清。

### 3. 队列改为任务组

| 报告要求 | 实现 | 证据 |
|---|---|---|
| ✅ 按 同一词 → 同一段同一规则 → 同章同类型 聚合 | `groupQueue`（`src/core/riskqueue.ts`） | `tests/riskqueue.test.js` 聚合 8 条 |
| ✅ 代表样本 3 条、影响计数、展开入口 | `samples`（默认 3）+ `<details>` 展开其余 | `tests/riskpanel_dom.test.js` 分组一条（数「折叠前」的卡片才作数） |
| ✅ 批量应用前显示将改动的词/段数量 | `batchImpact` | `tests/riskqueue.test.js` 影响面一条 |
| ✅ 全部应用 / 逐条查看 | 只对**动作统一**的组给批量入口（不是的一律逐条——宁可少一个按钮，也不做半对的事） | `tests/riskqueue.test.js` + `tests/riskpanel_dom.test.js` 各一条 |
| ✅ 明确的「本次完成」状态 | `sessionState`：只看**还有没有未处理的条目**，不看估时 | `tests/riskqueue.test.js` 完成态一条 |
| ✅ **删除「一小时最短路径」作为产品主入口** | 从页首降为折叠的「本次预算怎么排（后台估算，不是任务模型）」 | `tests/riskpanel_dom.test.js` 断言它在 `<details>` 里 |

## 三、真项目实测（不是夹具）

```
cd 名著阅读工作区_AnimalFarm
export LAYERTEXT_PROJECT=$PWD/调适项目_AnimalFarm.json
node <引擎>/tools/af_pipeline/LayerText_AF风险队列.mjs --tier A --chapters 1
node <引擎>/tools/af_pipeline/LayerText_AF三档复核.mjs --tier A,M --chapters 1,2
```

| 观察 | 数字 |
|---|---|
| 情节先验读到的素材 | 底线锚点 14 个、专名 24 个 |
| 队列卡片上的情节行 | `情节估计：高｜命中 底线原文锚点：willingdon beauty、角色/地名：jones…等 7 项` |
| 决策栏（跟着规则走） | `☐ ＋ 补上注释　☐ 退回重写　☐ 标记误报`＋一行效果说明 |
| **定位两条轴** | A 层：阅读负荷下降 **30%**（生词率 21.7% → 15.3%）｜理解支架覆盖率 **94%**（194/206 词型）<br>M 层：**43%**（21.7% → 12.4%）｜**93%**（145/156 词型） |

最后一行是这次最有用的一张数：**A 层几乎全是"加支架"而不是"降负荷"**（负荷只降 30%、支架覆盖 94%）。

> ⚠ **上面这几个数已经过时了，别拿它们当现状。** 那是 2026-09-11 当时的口径测出来的；
> 同日的词表口径修复（把数词与专名从生词里摘出去，`runQc` 改走 `loadLexicon()`）
> 让生词率与覆盖率同时变了。用当前代码在**当前产物**上重算是：
> **A 层 28%（16.5% → 11.9%）/ 96%**、**M 层 45%（16.5% → 9.1%）/ 98%**、
> **B 层 55%（16.5% → 7.4%）/ 93%**（Animal Farm 第一章）。
> 这一条**故意保留原样**——它是那一轮的记录，改写历史比标一行注更糟。
> 现状以 `tests/fixtures/replay/期望结论.json` 为准，`tests/replay.test.ts` 每次都会重算对数；
> README 里的数也绑在同一份冻样本上。
这个区别在任何合成指标里都会被抹平——正是 v4 报告要求两条轴分开说的理由。

## 四、本轮额外抓到并修掉的真实缺陷（都不在报告里）

| # | 缺陷 | 为什么危险 |
|---|---|---|
| 1 | `segmentSentences` 在没有 `[P##]` 标记时静默返回空数组 | **SENT-01（超长句）在单句场景下从来没生效过**——门禁看起来在跑、指标也在算，那条规则一直是死的 |
| 2 | `checkRewrite` 返回入参原文、而门禁判的是归一化后的文本 | "判 A 写 B"，两者会差一个段号前缀：**门禁说 `[P07]` 没问题、写进去的却是没有段号的一句** |
| 3 | 「删掉多余注释」删的是**第一次**匹配 | 语义正好相反：把首次那处（对的）删了，留下后面重复的（错的） |
| 4 | 动作失败后界面立刻重渲染队列 | **刚写上去的失败原因被覆盖**，教师只看到"点了没反应、卡片还在" |
| 5 | 补注按引擎报的词形去正则匹配 | 文中是 `Windmills`、引擎报 `windmill` → 直接失败、**静默什么都不做** |
| 6 | 风险决定的事件写入被 `void` 掉 | 写失败就是 **unhandled rejection**，在 App 里是一条无人处理的红字 |
| 7 | `ANNO-03` 展开时没带 `word` | 归不进"同一个词"那一档——而报告点名要按"同一词（漏注/释义冲突/重复注）"聚合 |
| 8 | 情节先验按句打分时被引号切断 | `Boxer said "I will work harder" in 1911.` 切成两半，含数字那半只剩 `in 1911.`——全书最重要的口头禅拿到的分和路人甲一样 |

## 五、还没做的（如实列）

- **四格实验仍未真跑**（要花 API 额度，用户选择自己挑时机）。所以「2%→98%」**至今没有归因结论**，
  只有"能归因的手段"。命令在 `docs/换书与续跑说明.md`。
- **定位只有数字，没有对外文案**：README 与界面上写了，但商业化文案、定价页这些不在仓库里。
- **撤销是单级**（有意为之，见 §2）；如果实测发现教师真会连续改主意多次，再考虑撤销栈。
