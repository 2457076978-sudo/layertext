# 换一本书怎么跑 · 口径与续跑说明

> 面向"第二个人来用"的场景。审查报告 §四 的原话：**对另一位老师，最可能卡在：
> 词表/路径配置、失败后是否可安全续跑、以及报告中多个覆盖率口径的含义。**
> 这份文档就回答这三个问题。管线怎么跑见 [快速开始](快速开始.md)；判定与队列的细节见
> [段级门禁与风险队列](段级门禁与风险队列.md)。

## 一、词表与路径：只有一个入口

所有路径、词表、书级配置都在**一个** `调适项目_<书名>.json` 里，脚本内不写死任何绝对路径
（2026-09-10 起；此前脚本里写死过 Animal Farm 的路径，是"换一本书第一步就断"的根源）。

```jsonc
{
  "书名": "Animal Farm",
  "工作区": "/abs/path/名著阅读工作区_AnimalFarm",
  "调适工作区": "/abs/path/…/调适工作区",     // 会话日志 / 决定日志 / 规则与底线
  "原文目录": "/abs/path/…/原文重制_M50",     // 每章一个 第X章/原文_规范化.md
  "产物目录": "/abs/path/…/重制三版",         // 每章一个 第X章/原文_<层>_<日期>.md
  "词库": "/abs/path/…/已知词汇库_v0.7.csv",  // 列：词,类型（类型∈{单词,课标词,待定词}）
  "书级": {
    "专名表": "…/专名_AnimalFarm.txt",        // 一行一名，# 开头是注释
    "知识库": "…/AF审校知识库_v1.csv",        // 列：类型,词,值,次数（类型=加注词）
    "词典":   "…/AF注释词典_v1.csv"           // 列：词,释义,来源（跨章同词同义的"正本"）
  },
  "日期": "2026-09-10",
  "章数": 10,
  "教材单元库": "…/教材单元_人教版.json",
  "教材进度": "九上:U4",                      // 可为 null（= 沿用整册词库口径）
  "引擎目录": "/abs/path/LayerText"
}
```

**找配置的三种方式**（脚本按此顺序找，`tools/af_pipeline/LayerText_AF词表与词典.mjs`）：

1. 环境变量 `LAYERTEXT_PROJECT=/abs/path/调适项目_X.json`
2. 从当前目录向上找 `调适项目_*.json`（最多 5 层）
3. 上次用过的项目（`~/.layertext.project` 指针；只在第 2 种方式命中时才写，临时跑别的书不会带偏默认）

### 词库的四个坑（都真发生过）

| 坑 | 症状 | 现在怎么防 |
|---|---|---|
| `类型` 列不写 `单词/课标词/待定词` | 整库词全被判成 OOV，生词率虚高 | 词表快照会报"来源读完却一个词都没有" |
| 只喂项目词库、不喂课标 1600 | `eighteen`/`three` 被当生词加注 | `loadLexicon` 统一并入课标 + 补录 + 项目词库 + 专名 |
| 词表/专名表/词典在三个脚本各读一份 | clover/squealer 被注成"三叶草/告密者" | 集中一份 + `LexiconSnapshot` 记版本与哈希 |
| 换了词表但没重跑 | 一本书里混着两版口径 | `清单 --verify` 直接判 blocked |

## 二、失败后能不能安全续跑

**能。** 但要知道"什么算已完成、什么不算"。

### `--resume` 的依据

会话脚本的 `--resume` 只认事件日志里的 `done` 事件。而：

- `done` **只在段级门禁判 pass 时写**；
- 门禁未通过的段写的是 `review` 事件，**不进 done**，正文里留
  `[P07] <!-- 本段未通过复检… -->` 占位；
- 于是同一条命令加 `--resume` 会**重跑那些没过的段**，而不是跳过它们。

### 每类产物在续跑时的行为

| 产物 | 会不会被覆盖 | 说明 |
|---|---|---|
| `产物目录/第X章/原文_<层>_<日期>.md` | 会（每段都重写整章） | 截断只丢一段，不丢整章 |
| `调适工作区/_会话/<层>.jsonl` | **不会**（append-only） | 续跑读它重建对话；`window` 事件会被重放成同样的裁剪 |
| `产物目录/_运行/<层>.完成.json` | 只在全通过时写 | 本轮不完整会**作废**旧标记 |
| `产物目录/_待复核/<层>/…` | 会（同一段覆盖） | 隔离副本 + 结构化问题 + 输入哈希 + 提示词版本 |
| `调适工作区/_决定/<层>.jsonl` | **不会**（append-only） | 教师决定，历史一条不删 |
| `产物目录/_运行/清单_<runId>.json` | 会（每次 `--stamp` 更新） | 运行身份 + 输入哈希 + 产物状态 |

### 什么时候**必须**重跑（不能续跑）

`清单 --verify` 会明说。它判 blocked 的情形：

- 词表/专名/知识库/词典/原文的哈希变了 → 新旧口径混在一本书里，比缺几段更糟；
- 产物在清单登记之后被改过；
- 还有未完成的段，或某一步骤失败。

**续跑前先跑 `--verify`**：如果它说输入漂移，加 `--resume` 只会把新口径接在旧产物后面。

## 三、报告里那些覆盖率，到底各是什么

一份报告里出现三四个"覆盖率"是这个项目的真实情况。它们的**分子分母各不相同**，
混着看就会得出错误结论（"2% 的加注覆盖率"当初就是这么被漏掉的）。
下表是唯一口径说明：

| 名字 | 分子 / 分母 | 谁在用 | 是不是门禁 |
|---|---|---|---|
| **①词表覆盖率**（注释后口径） | 非 OOV 的 token 数 / 全部 token 数 | QC 报告、`toLegacyReport` | 否，观测量 |
| **②生词率**（词型口径） | OOV 词型数 / 全部词型数 | QC 报告 | 否，观测量 |
| **⑪加注覆盖率** | 已注词型数 / **应注**词型数（OOV 去重、去两字母词、**去掉别处已注的**） | 段级门禁 `ANNO-01`、风险队列 | **是**（漏注即不可完成） |
| **生成覆盖率**（四格实验） | 模型**第一次**写出来的正文里，已注词型 / 应注词型 | 四格实验 | 否，实验指标 |
| **最终覆盖率**（四格实验） | 过门禁落盘的产物里，已注词型 / 应注词型 | 四格实验 | 否，实验指标 |
| **重复注释率** | 多余注释处数 / 注释总处数 | 四格实验、段级门禁 `ANNO-02` | 否（`ANNO-02` 是 warn） |
| **人工修订率** | 未过门禁的段数 / 段数 | 四格实验、运行清单 | 否，成本度量 |

三条要点：

1. **①和⑪不是一回事**。①问"学生认不认识这些词"，⑪问"该注的词注了没有"。
   2026-09-10 那次事故里 ①好看、⑪只有 2%——因为当时所有报表只统计"注了多少处"，
   根本没人算"该注多少"。**旧的"注了多少处"口径已降级为导出兼容字段，不再是质量门禁。**
2. **生成覆盖率单独展示是误导**（审查报告原话：论文好看但实用性不足）。
   它只反映"提示词与词表注入"的效果；落盘的成色看**最终覆盖率**。
   两者之差才是流水线（复检回流 + 本地去重 + 补注）的贡献。
3. **⑪的分母会随书推进变小**：一个词在第 1 章注过之后，后面章节不再计入分母
   （项目规则是"一个词全篇只注一次"）。所以逐章比较⑪时，要连着看整层的合计。

## 三之二、多人并行时怎么不互相覆盖

报告 §三 的第一条崩点就是并发写入。现在有两个开关：

| 场景 | 怎么做 |
|---|---|
| 只有你一个人、一次跑一层 | 什么都不用改（默认 `legacy` 布局，与从前完全一样） |
| 两位教师 / 同一本书多层 / 第二本书同时跑 | 建清单时加 `--layout run`：产物全部收进 `_运行/<运行ID>/`，跨运行不可能撞名 |

统一词典（唯一被所有运行共享且会被写的文件）现在**不会被并发覆盖**：生成阶段只写本运行私有的
`词典增量.json`，合并是显式的一步（`LayerText_AF词典合并.mjs`，已进管线）——加锁、原子替换、
基线优先。所以"明明配过的词下次又问一遍"这个老毛病不会再出现。

想查"某位教师对某个词做过的所有决定"：

```bash
node <LayerText>/tools/af_pipeline/LayerText_AF决定汇总.mjs --about windmill --teacher wayne
node <LayerText>/tools/af_pipeline/LayerText_AF决定汇总.mjs --by-rule
```

## 三之三、要把「2%→98%」写进论文时：先跑四格实验

报告 §二 的判断是：一次同时改了词表注入、会话记忆、查词和复检，**就没法归因**——
换个条件复现不出来。四格实验把变量拆开：

```bash
node <LayerText>/tools/af_pipeline/LayerText_AF四格实验.mjs --tier A --chapters 1
node <LayerText>/tools/af_pipeline/LayerText_AF四格实验.mjs --tier A --chapters 1 --dry    # 只打印计划
```

- 四个格子：**会话记忆**（一条会话 / 每段独立）× **全词表注入**（给全表 / 只给该注的词）；
- 固定项：同一模型、同一温度（0.3）、同一章、同一词表快照；
- 报告五个指标：**生成覆盖率**（模型第一次写出来的样子，从 append-only 日志取首轮响应）、
  **最终覆盖率**（落盘产物）、**重复注释率**、**人工修订率**、**token 成本与缓存命中**；
- 结论只给**单因子**增益（另一因子在两种水平上各测了一次）；
  缺首轮响应时会明确警告"生成覆盖率会被高估，别用它下判断"。

⚠ 会**真跑 4 遍**（消耗 API 额度）。实验产物带 `_exp1…_exp4` 后缀，**不碰正式产物**，
跑完回到正经生成命令即可。章越大越贵：Animal Farm 第 1 章 14 段是性价比最好的起点。

## 四、换一本书的最小步骤

```bash
cd <你的书目录>
cp <LayerText>/templates/调适项目_模板.json 调适项目_我的书.json   # ① 填路径
export LAYERTEXT_PROJECT=$PWD/调适项目_我的书.json                 # ② 指定配置

node <LayerText>/tools/af_pipeline/LayerText_AF清单.mjs --new --tier A --teacher 你的名字
node <LayerText>/tools/af_pipeline/LayerText_AF会话改写.mjs --tier A --dry    # ③ 先看预算，不花钱
node <LayerText>/tools/af_pipeline/LayerText_AF会话改写.mjs --tier A          # ④ 真跑
node <LayerText>/tools/af_pipeline/LayerText_AF风险队列.mjs --tier A          # ⑤ 只处理机器点名的
node <LayerText>/tools/af_pipeline/LayerText_AF清单.mjs --verify --tier A     # ⑥ 确认可交付
```

或者直接 `LayerText_AF管线.mjs --tier A`（开头建清单、每步盖章、结尾校验）。
想先验证环境而不花 API 额度：给生成脚本加 `LAYERTEXT_FAKE_LLM=exact`
（假模型走**同一条**判定与落盘路径，只是把模型换掉）。

在第 ④ 步之后、第 ⑤ 步之前，如果在 App 里做了决定，记得跑一次
`LayerText_AF决定汇总.mjs --tier A` 让决定变成待确认的入库提议。
