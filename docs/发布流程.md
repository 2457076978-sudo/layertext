# LayerText 发布流程

> 面向"一个人 + AI agent"的极简发布流水线。目标：修一个 bug → 打 tag → Release 页自动出现带 dmg 和说明的版本，全程零手动步骤（推送除外）。

## 版本规范（semver）

- **主版本 X**：不兼容的产品形态变化（本项目基本不动）
- **次版本 Y**：新功能（新指标、新页面、新导出格式）
- **修订号 Z**：修 bug、词表/提示词修订、文案调整

版本号出现的位置（发版前三处必须一致，见 [release-checklist](release-checklist.md)）：

1. `package.json` 的 `version`
2. `app/src-tauri/tauri.conf.json` 的 `version`
3. `app/index.html` 头部 logo 旁的 `<small>`（界面显示）
4. （文档性）`CHANGELOG.md` 新段落标题 `## [X.Y.Z] - 日期`

## 发版步骤

```bash
# 0. 前置（每次发版都要过）：见 docs/release-checklist.md，逐项打勾
# 1. 全量门禁（与 CI 同款；任何一步红都停止）
npm test && npm run eval
# 2. 更新版本号三处 + CHANGELOG 落一段 `## [X.Y.Z] - 今日日期`
# 3. 提交并打 tag
git commit -am "vX.Y.Z：一句话说明"
git tag vX.Y.Z
git push origin main --tags
# 4. 之后全自动：Release 工作流跑 测试门禁 → 构建 universal dmg → 提取 CHANGELOG 段落 → 创建 Release 挂 dmg
```

## CI / Release 工作流

- **CI**（`.github/workflows/ci.yml`）：每次 push / PR，ubuntu 上跑
  根目录 类型检查+全量测试 → `npm run eval`（低于质量基线即失败）→ 双引擎对照（TS vs Python）→
  桌面应用 tsc 类型检查。**不过绿不允许合并**。
- **Release**（`.github/workflows/release.yml`）：推送 `v*` tag 触发，macos 上先跑同样的测试+eval 门禁，
  然后 `npm run tauri build -- --target universal-apple-darwin` 构建 dmg，
  `tools/extract_changelog.mjs` 提取 CHANGELOG 对应段落作为 Release 正文（缺段落直接失败——防止"忘写说明就发版"），
  `softprops/action-gh-release` 挂 dmg 发布。

## 签名与公证：明确不做

**决定：不做 Apple 开发者签名与公证**（2026-09-06，W4 记录）。

理由：个人开源项目，Apple Developer Program 年费（$99）对单一开发者的免费工具不划算；
签名缺席的代价只是首次打开多一步"右键 → 打开 → 再点打开"，README 安装一节已写明且属正常现象。
若未来用户量显著增长或收到学校 IT 部门反馈（Gatekeeper 拦截影响部署），再重新评估——届时的成本
仅是购入证书 + 在 Release 工作流加 `APPLE_CERTIFICATE` 系列 secrets，流水线结构不变。
