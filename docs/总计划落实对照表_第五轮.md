## 一、本轮主体：把阶段 3 剩下的两条验收补齐

阶段 3 的验收清单里，有两条**从来没有被当回事**——它们既不是功能也不是性能，
而是"这个工具能不能被另一个团队拿去用"。两条都补上了。

### 1.1 「第二本书只需新建 manifest，不复制脚本」

这条原来做不到，原因朴素得有点刺眼：**一个写死在 10 个脚本里的数组**。

```js
const CN = ['一','二','三','四','五','六','七','八','九','十'];
const ch = `第${CN[i - 1]}章`;
```

抄十份本身已经够糟，更要命的是它**写死了"十章"**。换一本 12 章的书，
`CN[10]` 是 `undefined`，`第undefined章` 会一路拼进路径和报表，
**而脚本照常报成功**。真项目上没暴露，只因为 Animal Farm 恰好十章——
又一个"换本书才炸"的坑，而且炸得很安静。

新增 `src/core/chapters.ts`（纯逻辑）：

| 导出 | 作用 |
|---|---|
| `chineseNumeralToInt` / `chapterNameOf` | 中文章号 ↔ 整数（一~九十九），往返一致；`十十`/`一百` 这类**拒绝解析**而不是硬凑 |
| `chapterNamesFrom` | 从目录名挑章名并**按章号排序**——字典序会把"第十章"排到第二位 |
| `resolveChapterNames` | **配置 > 原文目录 > 默认（第N章 × 章数）**；最后那层逐字符复现旧行为 |

**为什么排序这件事值得单独写一段注释**：字典序的 `第一章、第三章、第九章、第二章…`
不是"稍微有点乱"，而是**顺序一乱，台账与汇总的行序跟着乱，
而对不上号的对照表长得跟正常表一模一样**。这类错没有人会当场发现。

接线：共享模块新增 `chapterNames(P)`（扫原文目录），10 个脚本那一行换成它；
`CN` 从"数字"变成**完整章名**，18 处 `` `第${CN[i-1]}章` `` 一并改成 `${CN[i-1]}`。

真项目实测：`[章节名] 10 章（来自原文目录）：第一章、…、第十章`——
与写死的数组结果一致，但这次是**从目录读出来的**。

### 1.2 「删除缓存不影响从 manifest 重建队列」

这条原来也做不到。清单里明明记着 `tiers` 与 `chapters`（"这次运行该覆盖哪些层、哪些章"），
而**此前没有任何脚本消费它们**：`风险队列.mjs` 的层与章一律从命令行来，
不给就自己猜一个默认。

后果很具体：把队列删掉之后，"重建"只能靠人回忆当初敲过什么，
**敲漏一章也不会有任何提示**，而漏掉的那一章会安静地不进队列。

- 共享模块新增 `readManifest(P, runId)` 与 `scopeOf(P, cli)`：范围按
  **命令行 > 清单 > 默认** 三层取，并把"这一项是从哪一层来的"打进日志——
  于是"这次为什么只扫了两章"当场可答。
- 实测（两章项目 + 清单写 A 层/1,2 章）：

```
[范围] 层 A层85（来自清单）｜章 1,2（来自清单）
队列里的章: 第一章、第二章
```

- 新增两条用例：删掉队列再跑（**都不给范围参数**）→ 除 `生成时间` 外**逐字段相同**；
  没有清单时如实说"范围只能靠命令行与默认"并给出"建一份清单"这个可行动建议。

**为什么把 `生成时间` 排除在外**：把它一起比会逼出"改时间戳让它相等"这种毫无意义的操作，
最后连这条用例本身也没人信了。比的是**事实**，不是时间。

## 二、阶段 3「禁止业务代码拼目录」的最后一处

12 个脚本里共 **55 处**写死 `${REPO}/dist/src/core/*.js`。这不是功能缺陷，
而是**没法拿一个还没装进共享 `dist/` 的构建去验证**——本轮两个并行子代理都因此只能测共享 `dist/`，
其中一个的隔离验证干脆做不成（它在报告里专门提了这件事）。

改成 `distOf(REPO)`（`LAYERTEXT_DIST` 可覆盖）。实测：
`LAYERTEXT_DIST=<repo>/dist-x` 跑 `对照台账.mjs`，它从独立构建里取引擎模块并正常出账。

## 三、回放层扩到全书十章 × 三档：当年出事的那几章从此被守着

第四轮只冻了第一章。而项目历史上有一次很严重的事故：**A 层第 7/8/9 章的加注覆盖率
只有 2%/3%/1%**，很久没人发现——因为当时的报表只统计"注了多少处"、没有"该注多少"。
**那三章正是此前完全没人守的地方。**

- 冻下 **10 章 × 3 档 = 30 组、669 条段级记录**，一组不缺。
- 每章加注覆盖率（A 层）：一 96.4%、二 93.3%、三 95%、四 90.1%、五 91.2%、六 92.4%、
  **七/八/九 100%（232/232、261/261、221/221）**、十 95.7%。**出事的三章现在是满的，
  而且从此它们的三条数被守着。**
- 全书两条轴：A 23%/97%、M 38%/93%、B 47%/93%。与第一章口径（28%/96%）**分开存**，
  `结论.口径` 里写明不许互相替代。

**输入仍然全份冻，没有精简**（320KB → 1.1MB）：要守的东西就在正文里——
漏注一个词 = 正文里少了一对括号；把正文剪掉等于把守卫剪掉。

几条刻意加上的守卫：

| 守卫 | 挡住什么 |
|---|---|
| **覆盖不许缩水**（棘轮 ≥10 章/≥30 组/≥225 段） | 有人"重新冻一次"时悄悄丢掉章节，让测试重新变绿 |
| **缺输入必须喊出来** | "跑通了"和"没跑"被混为一谈 |
| **分子分母成对**（已注+漏注=应注，任一章 <80% 就红） | 分母被悄悄改小 |
| **只读**（冻结前后各拍一次整棵树 sha256，不一致 exit 3） | 冻结工具反过来改真项目 |
| **反证常驻** | 守卫自己失效没人知道 |

**反证**：把第七章 A 层产物的 **171 个中文注全抹掉**（重演那次事故的形态）→
5 条用例当场失败，报出「A 层 第七章（加注覆盖率 100% → 0%，应注 232 → 232 词型）」；
恢复后 14/14。这条反证还做成了**常驻用例**，每次跑都在临时副本里重演一遍。

真项目只读证据：`303 个文件，指纹 37f9102576f7f0dc → 37f9102576f7f0dc`。

运行时间：常驻子集 1.4~2.4s；全书十章端到端由 `LAYERTEXT_REPLAY_FULL=1` 门控（+1.5s）。

## 四、这一轮我自己反复犯的同一个错

本轮我**四次**踩到同一类缺陷：新加的绑定落在使用之后（TDZ）。
三处是我自己写的新代码（`CN`、`ROOT`、`SHARED`），一处是我改别人文件时引入的
（`冻结回放.mjs` 的章节目录查找被改成 `原文目录/一/`，而真项目里是 `第一章/`——
子代理整份重写时才发现并修好）。

`node --check` **抓不到**它（只查语法），`tsc` 也抓不到（脚本是 `.mjs`，不在 tsconfig 里）。
抓到它的全是**真开子进程跑脚本**的那层用例。

结论不是"下一轮小心点"，而是：**动别人正在改的文件要打招呼**，
以及**新加一个绑定之后，第一件事是查它第一次被用到的地方在第几行**。

## 五、纪律第 3 条补完：App 层 30 处静默吞掉的 catch

判定链路与写正文事务此前已有结构性守卫，而 `app/src/**`（21 个文件、约 11.5k 行）
**从来没有被审计过**。这一层恰恰是"吞掉一个错误"最容易被看见的地方——
计划里点名的那句症状就叫「**点了没反应、卡片还在**」。

清点 **161 处 catch**：A 合规 63 ｜ B 有意兜底 68（逐条补上理由）｜ **C 静默吞掉 30（全部修掉）**。

### 5.1 最要命的一组：保存路径

| 位置 | 静默下来教师会看到什么 |
|---|---|
| `loadConfig` | 设置读不出来 → `S.appConfig` 变空、界面照默认跑；之后**任何一次保存都触发**（切章、记最近文件），**把空设置写回磁盘**——AI 配置、主题、阅读进度静默消失 |
| `loadShelf` | 书架显示为空，教师往里加一本书就**把整本注册表覆盖成一本** |
| 聊天自动保存 | 界面**刚写过**"（已自动保存）"，实际没保存 → 教师以为重启还能接着聊 |
| 三处审计日志 | 正文**已经改了**、toast 已说"已完成"，但变更日志那一行没落上 → 这次改动在审计链里**根本不存在** |

### 5.2 「读不到」被显示成「没有」

- 目录读不了却弹"这个文件夹里没有可处理的章节文件"——教师会去翻文件夹找自己"忘了放"的东西。
- ⭐ **`renderDataPane(...).catch(() => undefined)` / `openRiskPane().catch(() => undefined)`**：
  **这正是计划点名的那句「点了没反应、卡片还在」**，历史上就是这么写的。

### 5.3 假 0（纪律第 3 条的原话）

- `countRuleLeft` 解析失败时 `return 0` → 全书报告里"替换规则残留 0"＝"全书一遍没漏"，
  而这是拿去做交付判断、也是"是否人工复查"的判据。**假 0 等于替没核过的书签字。**
  现在返回 `null`，渲染成「—（没核到）」并进人工复查。
- 读不到的学生文稿被填成一排 0 → 与"学生交了个空文件"**一模一样**，教师会据此批评学生。
  现在给「—」+ ⚠ 并单列一节"这些行没能按正常口径算完（**不是**『学生没写』）"。

### 5.4 守卫与反证

`tests/appswallow.test.ts`：每一处 catch 必须**四选一**——说出去 / 抛出去 /
显式返回失败 / 写明「有意兜底」，**没有第五种**。用 TS 编译器 API 取值（不用正则：
注释里就有"被 catch 静默吞掉"这种话），判据跑在**剥掉注释后**的正文上
（`// setStatus(…)` 这种假修复不算数）。

两条防"守卫变成摆设"的用例：catch 命中数下限 ≥140、`有意兜底` ≥60——
目录改名或判据放宽导致"零命中却通过"时当场失败。

**注入反证（我自己复跑的）**：在 `shelf.ts` 里加一个 `catch { /* 尽力而为 */ }` →
`not ok 1 · shelf.ts:90 [try] catch { /* 尽力而为 */ }`；还原后 4/4。

### 5.5 已知残留风险（只让它可见，没有改行为）

备份读取失败与"文件不存在"在后端**分不出错误码**，所以"确有备份但读不出来"时仍可能覆盖备份。
真要根治得改返回契约，属设计改动，已写进注释。
**"只让它可见"是一个诚实的中间态，不是修完**——写在这里免得下次有人以为已经根治了。
