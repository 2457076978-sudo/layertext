# 文件架构地图

> **本文件是这套代码的"地图"。规矩只有一条，写死在最前面：**
>
> **任何改动目录结构、新增/删除/移动文件、或改变某个文件职责的提交，必须同步更新本文件，
> 并在同一个提交里完成。**
>
> 为什么把这一条放在最前：**改了不写，这张地图就开始骗人**——下一个人（或下一次的自己）
> 又得把整棵树重新摸一遍，而"每次都重新摸一遍"正是当初要立这份文件的理由。
> 地图过时比没有地图更坏：没有地图你会去看，过时的地图你会信。

维护方式：改结构时**顺手改本文件对应那一节**，并在文末「本文件自己的变更记录」加一行。
`npm run preflight` 会检查本文件存在且被 README 引用（见 `tools/preflight.mjs`）。

## 一、30 秒看懂

```
        ┌──────────────────────────── 用户碰得到的 ────────────────────────────┐
        │  app/  Tauri 桌面应用                                                │
        │    ├─ app/index.html + app/src/*.ts   界面（Vite 前端，31 个模块）    │
        │    ├─ app/src/styles/archive.css      样式（界面骨架在这里）          │
        │    └─ app/src-tauri/                  Rust 主进程（文件/钥匙串/窗口） │
        └───────────────────────────────┬─────────────────────────────────────┘
                                        │ 复用（同一条判定，不许两套）
        ┌───────────────────────────────▼─────────────────────────────────────┐
        │  src/  引擎：纯 TypeScript，**无 DOM / 无 Tauri / 大多无 fs**         │
        │    ├─ cli.ts / eval.ts               命令行与评测入口                 │
        │    └─ core/  48 个纯逻辑模块（质检 / 词库 / 门禁 / 台账 / 发布包…）   │
        └───────────────────────────────▲─────────────────────────────────────┘
                                        │ 命令行侧复用同一份
        ┌───────────────────────────────┴─────────────────────────────────────┐
        │  tools/af_pipeline/  32 个 .mjs 管线脚本（跑真项目的那条流水线）      │
        │  tools/              其余开发/校验工具（preflight、性能、词表转换…）  │
        └─────────────────────────────────────────────────────────────────────┘

  prompts/ 提示词    assets/ 内置词表    templates/ 项目模板    examples/ 示例（CC0）
  tests/   71 个测试  docs/ 48 份文档    CHANGELOG.md 变更历史  README.md 面向教师的总说明
```

**一句话分工**：`src/core` 是**判定**（纯函数，能单测），`app/` 是**界面与人机交互**，
`tools/af_pipeline` 是**跑真项目**（读盘、调 AI、落产物）。**同一条判定只许有一份实现**，
三边都从 `src/core` 取。

## 二、顶层目录

| 路径            | 是什么                                                              | 谁碰                      |
| --------------- | ------------------------------------------------------------------- | ------------------------- |
| `src/`          | 引擎（纯 TS）                                                       | 改判定逻辑来这里          |
| `app/`          | Tauri 桌面应用（前端 + Rust 主进程）                                | 改界面/交互来这里         |
| `tools/`        | 开发与运维脚本（含跑真项目的 `af_pipeline/`）                       | 改流水线来这里            |
| `tests/`        | 回归测试（71 个文件，983 项）                                       | 改任何东西都要来这里加/改 |
| `docs/`         | 项目文档（48 份）                                                   | 改机制要顺带改文档        |
| `prompts/`      | 版本化 AI 提示词（`manifest.json` 管版本）                          | 改提示词来这里            |
| `assets/`       | 内置词表（课标 1600 修正表等）                                      | 少动                      |
| `templates/`    | 新建项目用的模板（`调适项目_模板.json` 等）                         | 少动                      |
| `examples/`     | 示例文本与金标准评测集（自写 CC0）                                  | 少动                      |
| **`AGENTS.md`** | **动手前先读这一页**：三条铁律 + 门禁命令 + 仓库物理形态 + 既有口径 | 每次动手                  |
| `CHANGELOG.md`  | **每次改动都要写**（项目铁律）                                      | 每次提交                  |
| `README.md`     | 面向教师的总说明                                                    | 改能力/数字时             |

## 四、应用 `app/`

### 4.1 技术栈与构建

- 前端：Vite + 原生 TS（**无框架**），入口 `app/index.html` + `app/src/main.ts`
- 壳：Tauri 2（`app/src-tauri/`），窗口无边框、自绘窗控
- 打包：`cd app && npm run build`（Vite）→ `npx tauri build --bundles app`（Rust）→
  `cp -R .../LayerText.app /Applications/`

### 4.2 `app/src/` — 31 个模块（按域拆，前缀 `WP-F 拆分`）

## 六、测试 `tests/`

71 个文件、983 项。分层（见 `docs/复现机制.md`）：

| 层               | 是什么                                | 文件命名特征                                                  |
| ---------------- | ------------------------------------- | ------------------------------------------------------------- |
| 纯函数层         | 引擎逻辑，无 IO                       | `qc_rules` / `segmentgate` / `manifest` / `pendingqueue` …    |

| 孵化层           | 真跑管线脚本                          | `bundle_cli` / `pipeline_gate` / `pipeline_smoke` / `migrate` |

**`tests/fixtures/`**：只放**合成**夹具（`AI建议台账_样例.csv`、`风险队列_A层85_70条.json`）。
**真项目回放夹具不在仓库里**（含原书正文与教师产物），放在
`~/Documents/LayerText配置/回放夹具_真项目`，由 `LAYERTEXT_REPLAY_DIR` 指定；
找不到就整层 skip，见 `docs/复现机制.md`。

## 十、两个 worktree 与推送

本仓库有两个 worktree，**同一份 `.git`**：

| 路径                       | 分支                       | 是什么                                 |
| -------------------------- | -------------------------- | -------------------------------------- |
| `…/LayerText`              | `main`                     | 主仓（引擎与管线的主线）               |
| `…/LayerText-optimization` | `codex/total-optimization` | 特性分支（App 界面与新增机制的开发位） |

**项目配置里的「引擎目录」指的是主仓**（`…/LayerText`）——管线脚本 import 的是它的 `dist/`。
所以**引擎侧（`src/`、`tools/`）的改动要两边都落**，只改一边等于没改。

推送（网络有坑，详见 `~/.dsh` 里的记忆）：

```bash
git -c http.curloptResolve="github.com:443:140.82.112.3" \
    -c http.version=HTTP/1.1 \
    -c credential.helper= \
    -c "credential.helper=!/Users/wayne/.local/gh-cli/gh auth git-credential" \
    push origin <branch>
```

CI 在 GitHub Actions 上跑 `npm run verify`（preflight + typecheck + lint + test）。
**CI 的 `USER=runner` 是本机复现不出来的条件**——要预先自测，用
`USER=runner npm run verify`（历史上有整整一轮 CI 只因为这个变量假红）。
