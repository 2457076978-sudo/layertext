## 一、本轮主体：真项目回放层（纪律第 5 条的第三层）

计划原话：

> 5. 测试分成纯函数、事务故障、**真项目回放**三层；495 项全绿是底线，不是产品完成标准。

前两层都在问"这段代码对不对"，它们**回答不了**"我们报给教师的那些数还对不对"。
而项目里到处写着的那些数——A 层第一章 `SENT-01` = 19 句、阅读负荷下降 28%、
理解支架覆盖率 96%、风险队列 70 条压成 19 组——**此前没有任何东西在守着它们**。
一次重构让覆盖率悄悄从 96% 变成 93%，没人会发现，直到有人拿它去写论文。

### 1.1 做法

| | |
|---|---|
| 冻结工具 | `tools/af_pipeline/LayerText_AF冻结回放.mjs`：从真项目**只读**冻结输入与结论；`--check` 只对账不写文件 |
| 冻样本 | `tests/fixtures/replay/`，320KB |
| 回放用例 | `tests/replay.test.ts`（7 条） |

> ⚠ **这一节写的是第四轮当时的状态（只冻第一章）。第五轮已扩到全书十章 × 三档，
> 样本 320KB → 1.1MB、用例 7 → 14 条。** 不改写这一段（它是那一轮的记录），
> 现状见 `docs/总计划落实对照表_第五轮.md`。

**输入是「全份」冻下来的，没有精简。** 320KB = 整份词库（219KB）+ 词典 + 专名表 +
知识库 + 一层原文与三档产物。为什么不精简成"这一章用到的词"：
那会引入一个"精简后是否等价"的问题，而**那个问题得永远重新验证一遍**。

### 1.2 这一层第一天就抓到了一个错——**是工具自己的**

第一版工具自己 `buildLexicon({vocabCsvTexts:[…]})` 组词表，**漏了内置课标词表与专名表**，
于是算出"原文生词率 21%、A 层应注词型 79"，而项目自己的复核报告是
"生词率 16.5%、A 层应注词型 56"。

改成走共享模块的 `liveLexicon` 之后，**六个数与项目自己的报告逐位相同**：

| | 阅读负荷下降 | 理解支架覆盖率 |
|---|---|---|
| A 层 | 28%（16.5% → 11.9%） | 96%（54/56 词型） |
| M 层 | 45%（16.5% → 9.1%） | 98%（40/41 词型） |
| B 层 | 55%（16.5% → 7.4%） | 93%（26/28 词型） |

这件事值得记下来：**回放层的第一件事就是跟项目自己的报告对账**，
而它第一次对账就抓到了工具与被回放对象之间的分歧。
（把"两个东西不一致"当成"其中一个错了"来查，是这一层能起作用的前提。）

### 1.3 端到端的另一条腿

除了引擎层重算，回放用例还会在冻样本上**真跑项目自己的 `风险队列.mjs`**，
比对它产出的摘要：

```json
{"total":70,"blockers":67,
 "byRule":{"FACT-02":2,"ANNO-01":44,"SENT-01":19,"LEN-01":4,"ANNO-02":1},
 "byCategory":{"事实":2,"加注":45,"语言":23},"estimatedMinutes":37.8}
```

这与真项目跑出来的那一份**逐字段相同**。

### 1.4 反证

往冻结样本的 A 层产物里塞一个超纲词（`Notwithstanding`）：
第 1、2 条用例当场失败（4 pass / 2 fail）；恢复后 7/7 通过。
这一层不是"永远为真"的摆设。

## 二、顺带抓到并修掉的一个用户可见缺陷：README 的性能数字复现不出来

README 原来写着：

> 真项目实测：A 层阅读负荷下降 **30%**、理解支架覆盖率 **94%**；M 层 **43%** / **93%**

用当前代码在**当前产物**上重算（项目自己的复核脚本 + 独立回放工具，两边一致）是
**A 28% / 96%，M 45% / 98%**。全书口径也是 28% / 96%（A 层），
所以那三个数不是"章/全书口径不同"，而是 **2026-09-10 词表口径修复之前**留下的
（那次把数词与专名从生词里摘出去，生词率与覆盖率同时变了），**之后就再没人对过**。

README 是潜在用户和另一位老师最先看到的东西，上面写着一个复现不出来的性能数字，
**比不写更糟**。改法有两层：

1. 数字改成可复现的那一组，并写清**怎么复现**（样本与结论冻在哪）；
2. **把它绑到冻样本上**——用例从 `tests/fixtures/replay` 推出期望字符串，
   断言 README 必须包含它。**想改 README 里的数，就得先重新冻结样本**，
   也就是真的在真项目上重算一遍。这比"写的时候仔细一点"可靠。

反证：把 README 改回旧数字 → 该用例当场失败（6 pass / 1 fail）；恢复后 7/7。

`docs/v4方向_落实对照表.md` 里同样写着 30%/94%，但它**是那一轮的记录**，
所以**故意保留原样**、只加一行注（改写历史比标一行注更糟）。
"现状以哪里为准"现在有了明确答案：`tests/fixtures/replay/期望结论.json`。

## 三、阶段 3「四类实体有稳定 ID」：Artifact 的身份原来就是它的位置

计划原话：「Run/Artifact/Decision/Teacher **四类实体有稳定 ID**」。
Run 有 `runId`、Decision 有 `eventId`，而 **Artifact 把 `path` 当主键——身份即位置**。

按位置当身份会坏在三处，而且都是"不报错、结果错"：

- 搬家或换布局之后，**同一件产物被当成两件**；
- 同一件产物被两次运行各写一份、路径不同时，**永远比不出来**；
- 决定是挂在产物上的，产物一换身份，**历史决定就成孤儿**。

### 3.1 选了什么身份

身份 = **逻辑身份** `(kind, tier, chapter)` → `art-<12hex>`；
说不清自己是什么的登记项退化为路径身份 `art@<path>`；
两者都没有则**没有身份**（不凭空造一个哈希，否则空白登记项会凭空撞名）。

它**不是**什么（这几条比"是什么"更重要）：

| 不是 | 为什么 |
|---|---|
| **不是内容哈希** | `hash` 已经在回答"被改过"。内容进身份 = "重写一遍就是另一件产物"。**刻意保留的性质**：同一件被两位教师改成两份内容 → 身份相同、内容不同——这正是要报出来的「分叉」 |
| **不是随机 UUID** | 随机 ID 只在"登记那一刻"唯一；两次运行写同一件会得到两个 ID，**漏洞永远查不出**。而且它要求身份被持久化（清单被手写/拷贝就没了）。这里选的是**算出来的纯函数**，所以旧清单不需要迁移脚本 |
| **不是路径 / 运行 / 日期 / 书** | 路径回答"在哪儿"；运行与书都是身份的**外层**；`台账_…_09-10` 与 `…_09-11` 是同一件被写了两份 |
| **不取代 `path`** | `upsertArtifact` 的主键仍是路径——登记记的是盘上的事实 |

### 3.2 能力增益（我独立复核过）

两次运行把**同一件产物写到两个不同路径**：

```
旧口径： { ok: true }                          ← 永远查不出来
新口径： ok=false
         分叉｜正文｜A层85｜第一章｜art-f3cfc8c78f99
         runs  [runA, runB]
         paths [第一章/原文_A层85_09-10.md, _运行/runB/正文/第一章/原文_A层85_09-11.md]
```

**撞名还分了两种**：同一路径 = `覆盖`（真的会互相踩），不同路径 = `分叉`
（同一件产物有了两份内容，谁也不知道哪份是正本）。这两种要教师做的事完全不同，
混在一个"撞名"里说不清。

### 3.3 兼容与边界

- 旧清单**不需要迁移脚本**：身份是读的时候**算**出来的；`upsertArtifact`（`--stamp` 的入口）
  顺带补齐 `id`，幂等、只加一个字段。真项目那份 `artifacts: []` 的清单只读跑过，行为与从前一致。
- **已知边界**（写在代码里）：同一份清单内两件产物共用一个逻辑身份时
  （真实例：该层若干条待复核段落都是 `其他+该层+无章节`），该身份**退回路径比对**——
  宁可少报，不可误报。
- **四样里只齐了三样**：Teacher 仍是自由字符串，没有注册表与校验。

## 四、阶段 3「默认用 `run` 布局」：落差补齐了，但**默认值仍然不翻**

计划验收：「**两位教师同时对同一本书不同层级运行不会覆盖词典、日志或产物**」。
`legacy`（默认布局）下，两位教师同层同日跑同一本书，产物落在**同一个文件名**上——
这是真的会互相覆盖的。前面几轮把身份、指针、路径解析都修好了，
缺的只是"一个已有项目怎么安全地走到 `run` 布局"。

### 4.1 新增迁移工具（默认不动手）

`tools/af_pipeline/LayerText_AF迁移.mjs`：

| 旗标 | 作用 |
|---|---|
| **（无）** | **默认演练**：逐件打印"从哪儿搬到哪儿"、前置检查结果；**一个字节都不写** |
| `--apply` | 才真做；默认模式是**复制**（原件原地保留，迁移是加法） |
| `--move` | 搬完删原件（必须与 `--apply` 同用），删前逐件校验目标内容 |
| `--rollback` | 依据 `_运行/迁移_<runId>.json` 逐件记账回滚；**清单档案被删也照样能回滚** |
| `--to legacy` | 反向**只报告不做**（给了 `--apply` 也拒绝）：legacy 是共享命名，"两件撞同一文件名"是常态，工具无从判断该让谁赢 |
| `--only-registered` / `--allow-missing` / `--run` / `--teacher` / `--tier` | 收窄范围与处理边界情况 |

**关键设计：命名规则一份都没重写。** 清单只记 `kind/层级/章节`，没记日期、后缀、产物名；
而 run 布局里有四类产物的**文件名本身就变了**（`A层85.完成.json` → `完成.json` 等）。
工具先用**占位符**问 `resolvePath`"这类产物长什么样"，用模板反解出日期/后缀/产物名，
再把字段喂回去换布局重算。全部路径都从解析器来。

### 4.2 验证（12 条用例 + 6 组变异测试）

演练逐字节不动盘 · `--apply` 附加模式（原件逐字节还在）· `_运行/` 根那批**一件不搬、不改、不复制** ·
幂等 · **迁移完真跑一次上游脚本，它按 run 布局读正文、台账写在 run 落点，legacy 那份一字未动** ·
登记产物缺失则拒绝且零改动 · 目标已存在且内容不同则拒绝 ·
`--move` + `--rollback` 闭环 · 反向报告且拒不动手 · 两位教师各一份清单时**只动点名的那份**。

「变异测试」= 逐项把行为改坏后确认断言变红（默认就真做、搬家不改清单 `layout`、
复制模式顺手删原件……），证明这些断言不是 happy-path。

### 4.3 迁移工具的作者发现的**根因**（本轮已修，见 `77ba41f`）

`resolvePath` 的 run 布局分支**漏了 `suffix`**：legacy 是
`_待复核/A层85_试跑/` 与 `_待复核/A层85/` 两个目录，run 却是同一个文件。
runId 由「书+版本+层+教师+**输入哈希**」决定，所以**输入相同 ⇒ runId 相同**——
"先试跑看看、再正式跑"两次运行落在同一个运行私有目录里，待复核段落必然互相覆盖。
**待复核目录是那次失败唯一的记录**，被覆盖之后教师看到的是"这次没有段落被隔离"。

工具当时的做法是**拒绝迁移并点名**——那是对的（总比随便挑一件搬过去好），
但它绕的是根因。根因修掉之后，这条用例改成断言**迁移成功且两份都在**：
绕过去的问题不该永远留着"拒绝"当答案。

### 4.4 为什么**仍然没有**把默认值翻过来

不是漏做。翻默认值会让**教师已有的书换目录**，而"不破坏教师已有工作流"是硬约束。
正确的形态是本轮做的这样：**给出一次显式、可演练、可回滚的迁移**，
让需要并发的团队自己走过去——而不是替所有人做决定。
