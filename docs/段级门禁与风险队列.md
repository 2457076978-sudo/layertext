# 段级门禁与风险队列

> 2026-09-11 落地，对应《LayerText 项目审查报告（2026-09-11）》的 P0 与 §一。
> 一句话：**没通过复检的段落不再被算作完成；人工只看机器点名的地方。**

## 一、为什么改

原实现在 `tools/af_pipeline/LayerText_AF会话改写.mjs` 里：每段复检跑满 `--qc-rounds` 之后
**照常落盘并把段标为 done**，只有抛异常才进 failures。后果是——

- 一个反复不达标的段落可以一路进最终书稿，不触发任何失败；
- `--resume` 以 `done` 为准，于是它连"下次重跑"的机会都没有；
- 管线（生成 → 精修 → 补注 → 修复 → 复核 → 台账）全程显示成功。

确定性门禁形同虚设。这是**静默坏产物**，比模型写得差严重得多：它污染书稿，也污染论文里的数字。

还有第二个缺口：复检循环是「先判定 → 不达标才让模型重写」，循环跑满后**最后一次改写从未被判定**，
直接被当成结果落盘。

## 二、现在的判定口径

判定统一交给引擎的 `src/core/segmentgate.ts`（纯函数、可单测、每条问题带规则号），
不再由脚本各自拼 `probs` 字符串。规则分两级：

| 规则 | 类别 | 级别 | 后果 | 概率 | 风险 | 含义 |
|---|---|---|---:|---:|---:|---|
| `FACT-01` | 事实 | warn | 22 | 0.6 | **13.2** | 原文的数字在改写里找不到 |
| `FACT-02` | 事实 | warn | 20 | 0.6 | **12.0** | 原文的专名在改写里找不到 |
| `ZH-01` | 格式 | blocker | 11 | 1.0 | **11.0** | 注释之外混入中文 |
| `ANNO-01` | 加注 | blocker | 10 | 1.0 | **10.0** | 超纲词没加注 |
| `SENT-01` | 语言 | blocker | 8 | 1.0 | **8.0** | 句子超过本层句长上限 |
| `ANNO-03` | 加注 | warn | 9 | 0.7 | **6.3** | 注释释义与统一词典冲突 |
| `LEN-01` | 语言 | blocker | 6 | 1.0 | **6.0** | 篇幅偏离目标 ±12% 以上 |
| `ANNO-02` | 加注 | warn | 5 | 0.9 | **4.5** | 同一个词注了不止一次 |

- **blocker** = 不通过就**不可完成**：不写进正文、不进 `done`、落隔离目录、进程非零退出。
- **warn** = 通过，但进**风险队列**按 `风险 = 概率 × 后果` 排队等人工。
  事实类机器判不准（改写可能合法地换说法），所以不阻塞；但后果最重，所以置顶。

规则表 `GATE_RULES` 是唯一口径：门禁、风险队列、报告都从它取元数据。
改优先级只改这一张表，排序验收测试（`tests/riskqueue.test.ts`）会挡住破坏报告既定优先级的改动。

## 三、产物与退出码

跑 `node tools/af_pipeline/LayerText_AF会话改写.mjs --tier A`：

| 路径 | 什么时候写 |
|---|---|
| `产物目录/第X章/原文_<层>_<日期>.md` | 每段都写。未通过的段留 `[P07] <!-- 本段未通过复检… -->` 占位 |
| `产物目录/_运行/<层>.完成.json` | **只在全部段落通过时写**；本轮不完整会作废旧标记 |
| `产物目录/_运行/<层>.待复核.json` | 有未通过/异常段落时写（失败清单） |
| `产物目录/_待复核/<层>/第X章_第N段.{md,json}` | 每个未通过段落的改写正文 + 结构化问题 + 输入哈希 + 提示词版本 |
| `调适工作区/_会话/<层>.jsonl` | 事件日志：`msg` / `done` / `review` / `warning` / `stats`（append-only，可续跑可回放） |

退出码：**非零**（1）当且仅当有段落未通过或异常。管线脚本会因此中止，不会带着缺口往下跑。

占位符写成 HTML 注释是刻意的：教师打开文件一眼看到缺口在哪，
而分句/分词（`textpipe`）不含 2 个以上连续字母，**不会污染任何 QC 指标**；
同时它保住了后面段落的**位置**——否则第 8 段的原句会被配到第 7 段的改写上。

## 四、人工怎么用

```
node tools/af_pipeline/LayerText_AF风险队列.mjs --tier A
```

产出：

- `产物目录/风险队列_<层>_<日期>.md` —— 人看的勾选式清单
- `产物目录/_运行/风险队列_<层>.json` —— App 阅读器与离线汇总器读的机器格式

每条包含：**原句 / 改写句 / 上下文各一句 / 触发规则号 / 风险分 / 位置**，
底部三个决策框：☐ 采纳改写　☐ 退回重写　☐ 标记误报。

清单开头给「一小时最短路径」：

| 阶段 | 分钟 | 做什么 |
|---|---:|---|
| 看统计与最危险队列项 | 10 | 判断这一层整体是否可信 |
| 处理事实/专名/数字差异 | 25 | 逐条回原文核对——唯一机器判不准、后果又最重的一类 |
| 处理全部漏注与超纲释义 | 15 | 对照统一词典，改完的释义进词典，后面章节自动一致 |
| 抽查每章首尾及高风险段 | 10 | 剩下的语言类问题按风险顺序扫 |

队列估时超过预算（默认 60 分钟）时，脚本给的建议是**先修生成规则或词库**，不是加班。

## 四之二、教师决定：不可变事件，不是 mark JSON

报告 §一的第二条要求：教师修改不能只写标记 JSON，必须**追加不可变事件**。
事件日志是 append-only JSONL（一行一条、只增不改），存在
`调适工作区/_决定/<层>.jsonl`：

```json
{"schemaVersion":1,"itemId":"第一章#2:FACT-01:1911","decision":"false-positive",
 "before":"In 1911 Napoleon gave a speech.","after":"In 1911 Napoleon gave a speech.",
 "reason":"年份是教学锚点，不能删","ruleIds":["FACT-01"],
 "teacherId":"wayne","timestamp":"2026-09-11T10:05:00.000Z","sourceVersion":"sha-abc",
 "chapter":"第一章","segIndex":2,"subject":{"kind":"number","value":"1911"}}
```

| 字段 | 为什么必须有 |
|---|---|
| `itemId` | 风险队列项 ID。没有它就回答不了"这条决定是关于什么的" |
| `decision` | `accept` / `reject` / `false-positive` / `edit` —— 三个按钮 + 直改 |
| `before` / `after` | 教师看到什么、改成了什么（事后复盘唯一依据） |
| `ruleIds` | 哪条规则报的——**误报率是规则噪音水平的直接度量** |
| `teacherId` | 多教师并行时能否审计 |
| `timestamp` | 后写覆盖先写（教师改主意是常态），但历史一条都不删 |
| `sourceVersion` | 产物版本哈希：这条决定是对着哪一版做的 |

《AI建议台账.csv》（`src/core/adoption.ts`）与事件日志的分工：
**台账是可重建的分析视图，事件是不可变的事实**。所以事件是正本、台账由事件导出，
而不是两份并行维护——并行维护正是"词表/词典口径漂移"那类事故的成因。

### 离线汇总：只提议，不入库

```
node tools/af_pipeline/LayerText_AF决定汇总.mjs --tier A
```

把决定汇总成三条通道的**待确认提议**（写 `产物/_运行/入库提议_<层>.md`）：

| 通道 | 触发条件 | 提议什么 |
|---|---|---|
| `dict-entry` | 同一个词的释义被**采纳** ≥2 次 | 写进统一词典，后续章节自动一致 |
| `kb-exception` | 同一个词被**标记误报** ≥2 次 | 进词表例外，工具不再对它报警 |
| `rewrite-template` | 同一条规则下教师**直改** ≥2 次 | 固化成改写模板并写进提示词 |

外加「被反复改主意的项」清单：同一个 `itemId` 上出现多种决定，
说明**规则或词条本身有问题**，该先修规则而不是继续人工判。

提议对象恒带 `requiresConfirmation: true`；真正落库必须显式
`--apply 1,3 --yes`，且落库本身也写一条 `_决定/_入库.jsonl` 留痕。

## 五、自检（不调 API）

门禁"真的拦得住"这件事必须能被自动断言，不能靠人肉试：

```
LAYERTEXT_FAKE_LLM=long  node tools/af_pipeline/LayerText_AF会话改写.mjs --tier A --out 自检  # 永远超长 → 必不过
LAYERTEXT_FAKE_LLM=exact node tools/af_pipeline/LayerText_AF会话改写.mjs --tier A --out 自检  # 按目标词数回放 → 必过
```

`LAYERTEXT_FAKE_LLM=<字面文本>` 则直接返回该文本。假模型走的是**同一条**判定与落盘路径，
只是把 `callChat` 换掉，所以它证明的是真实行为，不是另写一套测试代餐。

`tests/pipeline_gate.test.ts` 用子进程跑真脚本，锁定四条：

1. 永远超长的 mock 响应 → 没有完成标记、坏产物不进正文、退出码 1、失败清单与隔离副本都在；
2. 通过的段 → 正文与完成标记都写、退出码 0（门禁不能只会拦）；
3. 未通过的段不进 `done`，`--resume` 会重跑它而不是跳过；
4. 本轮不完整时，上一轮留下的完成标记会被作废（否则旧标记掩盖新失败）。

## 六、跟旧口径的关系

- 「只统计注了多少处」的旧报表口径**降级为导出兼容字段**，不再当质量门禁
  （它曾让 A 层第 7/8/9 章 2% 的加注缺口完全隐形）。兼容字段仍在 `toLegacyReport` 里，导出的 JSON 不破。
- 加注覆盖率不再用字符串正则统计：注释改为 token 级解析（`src/core/annot.ts`），
  按**词形与连字符成分归一**判定，并单独报出重复注释、释义冲突、靠归一才命中的词型。
- `known = lex.known ∪ IRR ∪ gloss ∪ reinforceList` 的取舍保留，但只有在提供复现队列时
  额外报「原始 OOV」「复现豁免掉的 OOV」「原始生词率」三笔账，让"本应教学注释却被豁免"可被审计。
